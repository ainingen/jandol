# 事務所を部屋にする — 設計（A6）

作成 2026年9月4日。**設計だけ。まだ実装していない。**
`docs/design/office/spec.md` の五段階（A1〜A5）が閉じたあとの一手。
事務所まわりの決めごと（`parlor.day`・`assign`・依頼・疲労）は `spec.md` のまま動かさない。
**ここで変えるのは見せ方と入口だけ**で、データもゲームの数値も動かさない。

---

## 0. 何をするのか（なぜ部屋か）

いまの事務所は機能を縦に並べた一覧で、部屋になっていない。
実測すると **380px 幅で朝の画面は縦 2,824px、およそ4画面ぶん**ある
（所属8人・依頼5件のセーブ。`tools/` の測定ではなく、ブラウザで
`#scroll.scrollHeight` を読んだ）。上から順に

```
見出し → 所持金の帯 → 「今日を始める」 → 所属8〜14行（配置・シフト・疲労・調子）
→（遠征中なら店の絵）→ 届いている話 N 件 → 雀エイト8行 → 遠征に出る → 扉5つ
```

所属が14人になり、依頼が増え、雀エイト表が入り、と**足すたびに縦へ伸びた**。
この先も足す（客タイプ・男性への声かけ・課題・ライバル）ので、一覧のままだと必ず破綻する。
一方で下の階の雀荘は絵として作り込まれていて、**上の階が表なのは釣り合っていない。**

**事務所の一室を絵として描き、物をタップして各機能へ入る形にする。**

狙いは一つ——**物が増えても一覧が伸びない。**
項目が増えたら部屋に物が増えるだけで、縦には伸びない。
設計はここを外さない。**「部屋の下に一覧を続ける」は禁じ手**——
それをやると、絵が一段増えただけで前と同じ縦並びになる。

---

## 1. 条件（指示。破らない）

- **雀荘と地続きに見えること。**上の階と下の階が別のゲームに見えてはいけない
- **canvas は使わない**（表紙のみ）。雀荘と同じ **SVG の `crispEdges` 矩形**で描く
- **380px で成立すること。**物が小さすぎて押せない、が起きないように
- **既存の機能を落とさない。**いま朝の画面にあるものは全部どこかに置く（§4 の対応表）
- **未読・要対応があることが、開かなくても部屋を見れば分かる**（§5）

### 2.4 横送りはしない

雀荘は 200 の論理幅を狭い端末で横に送って見せるが、**部屋では送らせない。**
入口である部屋の一部が隠れていると「何が押せるか」が分からない。
だから押せる物を x 10〜190 に収め、横送りの矢印は出さない
（`mount` に `room: true` を渡したら矢印を作らない）。
倍率が 2 に落ちるいちばん狭い端末（〜360px）でも、この範囲は必ず見える。

## 3. 描画をどう作るか（`jansou-floor.js` を流用するか）

**判断：描画の道具は流用し、床の `mount` は流用しない。新しい `src/office-room.js` を切る。**

### 3.1 流用するもの

`JansouFloor` から出ているものをそのまま使う。

- **画素の描法**：`el` `rect` `gridRects`（文字グリッド → `<rect>` の束）。
  **新しい描法を作らない。**同じ関数で描くから同じ粒になる
- **倍率**：`fit(availW)` と `floorToScreen()` の考え方。同じ端末で同じ倍率
- **寸法**：`FLOOR_W` `FLOOR_H` `WALL_H` `CARPET_Y` `SEAT_W` `SEAT_H`
- **色**：`PAL`（＝ `PAL0`。`tools/test-scout.js` が錠を掛けている値）
- **人**：スタッフの体 `STAFF_BODY` と `staffColor`（第四段で所属の子を立たせるとき）。
  **下の階で制服を着て歩いている同じ絵が、上の階に居る**——これが地続きのいちばん強い形
- **設置物の絵**：ソファ・観葉植物（`drawFixtures` が描いているもの）
- **枠の CSS**：`.jnFloor` `.jnFlTop` `.jnFlStage` `.jnFlTicker`。
  部屋用の差分は `office-room.css` に**上書きで**足す（`.ofRoom` を付けて分ける）

このうち `el` `rect` `STAFF_BODY` `staffColor` は**いま export されていない**。
export に足すだけ（振る舞いは一つも変えない）。`gridRects` は出ている。

### 3.2 流用しないもの

- **`JansouFloor.mount()` そのもの。**1,300行の再生機（タイムライン・席・
  ハート・模様替え・横送り・割り込み）で、部屋に要るのは
  **静止した一枚＋当たり層＋常時アニメの時計**だけ。
  擬似 `parlor` を作って `mount` に食わせる案は、遠征先の店で一度通った道で、
  `normalize()` の丸めや卓の前提が混ざる（`CLAUDE.md`「スカウトまわりの急所」）。
  部屋には卓が無いので、そこを避けるためだけの細工が増える
- **`drawWall`。**雀荘の壁はネオンの看板と貼り紙で、事務所の壁ではない。
  部屋の壁と物は `office-room.js` が自分で描く（`rect` と `gridRects` で）
- **マス目（`GRID` `KINDS` `canPlace`）。**部屋の物は動かさない。固定座標でよい。
  模様替えを部屋に持ち込むのは「やらないこと」（§12）

### 3.3 `office-room.js` の形

```
OfficeRoom.mount(host, opts)      枠を作る。opts.title / opts.sub（上の帯）
  .render(view)                   一枚描く。view は純関数 roomView(st) の出力
  .idle()                         時計を進める（PC の光の明滅・窓の雲）。乱数は使わない
  .on(key, fn)                    物を押したとき（'mail' 'board' 'desk' 'eight' 'door' 'run'）
  .destroy()                      rAF を止める。**画面を替えるときは必ず呼ぶ**

OfficeRoom.layout()               置くものの一覧（§2.2 の表）。純関数。テストが読む
OfficeRoom.roomView(st)           セーブ → 部屋の見え方（未読数・付箋・額の金・窓・扉の札）。純関数
```

`roomView` が純関数なのは、**印の出る条件を node のテストで固定するため**（§11）。
`render` は `roomView` の出力を読むだけで、セーブに触らない。

**常時アニメは `live.clock` の位相だけから描く。乱数を混ぜない**
（遠征先の店と同じ決めごと）。PC の光は 1.2秒周期の明滅、窓の雲は 20秒で一往復。
**形は動かさない。動くのは明るさと雲の位置だけ**（癖で覚えたこと。`scout/spec.md` §4.5）。

## 5. 印（開かなくても部屋を見れば分かる）

| 状態 | 部屋に出る印 | 読む場所（`roomView`） |
|---|---|---|
| **未読の依頼がある** | PC の画面がシアンに光る（明滅）。当たり層に件数の丸札 | `offers` のうち `mailRead` に無い id（§9） |
| 課題（`quest`）が届いている | 同じ受信箱。件数に含める | 同上 |
| 遠征中で受けられない | PC は光るが、札が灰色 | `tripOf(st)` |
| **誰かが疲労・限界** | 事務机に赤い付箋（一枚。人数は名簿で） | `fatigueBand(v).key` が `tired` か `limit` |
| うちの子が雀エイトに入っている | 額の縁が金 | `eightTable(st).some(mine)` |
| 順位が動いた朝 | 額に小さな朱の丸 | **持たない**（§13。`eightDay` を足すかどうか） |
| 店が無い | 扉に「空き店舗」の札 | `parlor.open` |
| 遠征中 | 枠が店に替わる（§7）。部屋は出ない | `tripOf(st)` |
| 出勤が0の帯がある（店は開いている） | ボードの列に空きが見える（磁石が無い列） | `Jansou.shiftOf` |
| 朝／夜 | 窓の空。夜は部屋が暗く、机のランプだけ | `screen` |

**印は必ず二つの層で出す。**画素の層に**形と色**（光る画面・赤い付箋・金の額）、
当たり層に**数字**（件数）。**画素の層に文字を置かない**
（`jansou-floor.css` の冒頭の決めごと。ドットの世界に日本語を置くと潰れる）。

**「印が出ている＝押せば何かできる」を守る。**印だけ出て開いても何も無い、を作らない。
逆に、押して初めて分かる要対応も作らない——それは一覧に戻る道。

## 6. 夜と日報

**同じ部屋が夜になる。**壁と床に `pal.night` の膜（雀荘の `drawLight` の夜と同じ手）、
窓は紺に月、机のランプだけ点く。PC の光は消す（依頼は朝に届くので、夜に未読は増えない）。

**日報は机の上の一枚。**夜に部屋へ来た瞬間、**日報のシートが開いた状態で出る**——
夜にやることは日報を読んで明日へ進むことだけなので、机を探させない。
シートの中身は**いまの `renderNight` の四つの型（店が無い日・遠征中・帰還・依頼）をそのまま**。
シートの一番下が「明日へ」。

シートを閉じる（取っ手を下げる）と夜の部屋が見え、下の帯が「明日へ」になっている。
夜でも机・ボード・額は押せる（名簿を見てから明日へ、ができる）。
**PC は押せる（読み返せる）が、受ける釦は出さない**——受けるのは朝
（§8.1 の「受けるか見送るかを朝に決める」）。

**「明日へ」は日を進めない。**夜を畳んで朝へ戻すだけ（`spec.md` §6.1 の訂正のとおり）。

## 7. 遠征中の朝

代表は部屋にいない。**枠に入るのは部屋ではなく滞在先の店**（`scout/spec.md` §2〜4 の
静止した一枚。**いまの `mountShop` のまま**）。同じ枠・同じ倍率なので、
「上の階（部屋）」「下の階（店）」「よその店（遠征先）」の三つが同じ窓で入れ替わる。

部屋の物のうち遠征中に要るのは、名簿（配置・シフトは変えられる）・ボード・
メール（**見送る**はできる。受けるは不可）・雀エイト。
枠の下に**「事務所に電話する」の一行**を置き、四つの小さな釦（名簿・ボード・メール・掲示）で
同じシートを開く。電話なので**扉は無い**（雀荘へ降りる・遠征に出るは遠征中にできない。
いまと同じ）。

下の帯は「今日を始める」のまま（`runTripDay` へ）。一行は
「○○県に遠征中。あと N 日。留守は △△ に任せています」で、いまの文面のまま。

発見の札（`shopFound`）と声かけの残り回数（`shop.calls`）は、店の枠の上下に**いままでどおり**。

## 8. シート（物を押したときの開き方）

**部屋の上に、下から引き出しが上がる。**画面を替えない（`go()` を呼ばない）。
`office.js` の内部状態 `sheet`（`null | 'roster' | 'board' | 'mail' | 'eight' | 'door' | 'report'`）
で持ち、`render()` が部屋の上に描き足す。取っ手を下げるか部屋の暗い所を押すと閉じる。

| シート | 中身 | 第一段での作り |
|---|---|---|
| `roster` 名簿 | 所属一覧（いまの `.ofMate` の行そのまま） | **既存の HTML をそのまま移す** |
| `board` ボード | 配置とシフト | 第一段は `roster` と同じ行。**第三段でボードの絵に**（§10） |
| `mail` メール | 届いている話（いまの `.ofOffer` そのまま）。開いたら `mailRead` に入れる | 既存の HTML をそのまま移す |
