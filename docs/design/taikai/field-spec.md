# 出走表 — `docs/design/taikai/field-spec.md`

対象は `src/taikai.js` の `renderField()` と `src/taikai.css` の「出走表」節だけ。
`prepare()` / `runTournament()` / `buildField()` には**一行も触らない**。
出走表は表示だけの画面で、卓割りも抽選もここより前で終わっている。

---

## §0 なぜ直すか

いまの出走表は、64人が全員おなじ `.tkName`（11.5px・灰・背景 `rgba(0,0,0,.22)`）で並ぶ。
金色になるのは自事務所の四人だけ。**情報に格差がないので、目が止まる場所がない。**

足りていないものが三つある。

- **賞金が出ていない。** 何のために打つのかが画面にない
- **回戦の数が出ていない。** 何回打てば終わるのか分からない（「いきなり決勝が始まる」の半分はここが原因）
- **大会の格が出ていない。** `.tkRoot` は五つの大会で完全に同じ見た目で、新人戦と雀エイト選抜戦が区別できない

---

## §1 決めたこと

| 問い | 決定 | 理由 |
|---|---|---|
| 全員の名前を残すか | **残す。畳まない** | 知っている子を探すのが出走表の楽しみ。畳むと画面は締まるが、その楽しみごと畳むことになる |
| 注目の三人の選び方 | **因縁を優先し、足りなければ強さ順** | 強さ順だけだと毎回おなじ顔ぶれになる。因縁枠は初回は空になるので、強さ順が受け皿として要る |
| 入場の演出 | **タイトル戦と雀エイト選抜戦だけ。無音。復帰時は出さない** | 大会は依頼から何度も入る画面。日常の大会で毎回止まると三回目には邪魔になる |

**注目に出した子を、下の全員一覧から消さないこと。**
上で見た名前を下で探して見つからないと、壊れて見える。二か所に出てよい。

## §2 画面の構成（上から）

```
① 見出し帯      大会名／出走人数        ← 大会ごとの色（§4）
② 賞金と梯子    優勝 3,000,000円
                64名 → 16卓 → 4卓 → 決勝卓
③ あなたの事務所  顔つきカード ×4
④ 注目の雀ドル    顔つきカード ×3
⑤ 出走全員       いまの .tkGroup / .tkName のまま（段位ごと）
⑥ 卓に着く
```

復帰の一言（`.tkResume`）は**いまと同じ位置**、①の直後に入る。
`resume` があるときは「卓に着く」を出さない現行の分岐をそのまま残す。

### ③ あなたの事務所

四人を横一列のカードに。順序は**自分が先頭**、あとは `st.team` の順。

カード一枚に載せるもの：

- 顔（`img/…webp`。§7）
- 名前（`var(--maru)` 太字）
- 段位（自分は `st.playerRank`、仲間は `gradeOf(comp)`）
- 打ち筋（`STYLES[c.style].name`。**自分には無いので出さない**）
- 完成度バー（`.tkFill` を流用。**自分には無いので出さない**）
- 調子（あれば。§6.2）

自分のカードだけ縁を金にして、他の三人と差をつける。
`.tkNames` の `own` と役割が重なるが、**下の一覧の金色はそのまま残す**——
上のカードは「誰が出るか」、下の金色は「一覧の中でどれが自分たちか」で、目的が違う。

**カードに出す完成度と段位は、出走表そのもの（`prepared.field`）から引く。**
`teamCards()` を別に引き直すと、`Office.tableCardOf` が乗せた疲労と調子のぶんだけ
上のカードと下の一覧で段位が食い違い、**同じ子が二つの級に出る。**

### ④ 注目の雀ドル

三人。カードの作りは③と同じだが、**一人ずつ一行の見出し語を持つ**。

- 因縁枠 … `前に当たって、勝てなかった相手`
- 強さ枠 … `優勝候補`

**「この中の誰かと当たります」とは書かない。** 卓割りはまだ決まっていない。
一回戦で当たらないことも、決勝まで一度も当たらないこともある。

## §3 注目の三人の選び方

`renderField()` の外に純関数として置く（テストできるように）。

```js
/* 因縁 → 強さ の順に三人まで。自事務所は入れない */
function pickSpotlight(field, st, n = 3) { … }
```

順序：

1. **因縁枠**——`st.recent` に入っていて、`st.beaten` に**入っていない**相手
   （＝前に当たったが、まだ自分より上に来られていない相手）。
   `st.recent` は新しい順なので、**先頭から**取る
2. **強さ枠**——残りを `strengthOf(c, STYLES)` の降順で埋める
3. どちらも自事務所（`[0].concat(st.team)`）を除く
4. 同じ子を二度入れない

`st.recent` は `finish()` が `run.met.slice(0, 40)` で書いている。
`st.beaten` は一度勝てば積み上がったまま消えない。だから因縁枠は
**「取りこぼしたまま」の相手だけ**になり、倒すと自然に卒業していく。これでよい。

初回は `recent` が空なので、三人とも強さ枠になる。それも正しい姿。

**強さが同じなら id で固定する。**雀エイト表と同じ理由——開くたびに
並びが揺れると、表として読めなくなる。

## §4 大会ごとの色

`.tkRoot` に `data-tier` を付けて、CSS変数だけ差し替える。
**新しい色を要素ごとに書かないこと**——変数を一段挟むのは、あとで色を変えるときに
一か所で済ませるため。

```css
.tkRoot{--tk-accent:var(--gold);--tk-accent-dim:var(--gold-dim)}
.tkRoot[data-tier="rookie"]{--tk-accent:#7fb08a;--tk-accent-dim:rgba(127,176,138,.38)}
.tkRoot[data-tier="local"] {--tk-accent:#6d8fb8;--tk-accent-dim:rgba(109,143,184,.38)}
.tkRoot[data-tier="open"]  {--tk-accent:#b9c2c6;--tk-accent-dim:rgba(185,194,198,.38)}
.tkRoot[data-tier="title"] {--tk-accent:var(--gold);--tk-accent-dim:var(--gold-dim)}
.tkRoot[data-tier="eight"] {--tk-accent:#c0392b;--tk-accent-dim:rgba(192,57,43,.42)}
```

`--tk-accent` を使うのは、**見出し帯の罫・カードの縁・梯子の線**の三つだけ。

**賞金は大会によらず金のまま**（`var(--gold)`）。
金は「お金の色」として `.tkPrize` / `.tkPrizeYen` / `.tkChampion` で既に働いている。
大会ごとに賞金の色が変わると、その意味が壊れる。

`data-tier` は**出走表と進行と結果の三画面すべて**に付ける（`root.dataset.tier`）。
一枚だけ色が違うと、間違いに見える。大会が終わって `renderSelect()` に戻るときは外す。

### §4.1 罠 — `root` の `data-tier` は大会選択の釦と同じ名前

大会選択の画面の釦は `<button class="tkTier" data-tier="open">` で、
`root` の click は `e.target.closest('[data-tier]')` でそれを拾っていた。
**`root` 自身に `data-tier` を付けると、出走表のどこを押しても `closest` が
`root` に当たり、`start()` がもう一度走って顔ぶれが引き直される。**

拾い口を **`button[data-tier]` に狭める**こと。釦は元から `<button>` なので
選択の画面の振る舞いは変わらない。`tools/test-taikai-field.js` が錠を掛けている。

## §5 勝ち上がりの梯子

人数から作る。**数を書き写さないこと**——大会の `size` を変えたときに必ずずれる。

```js
/* 16人 → ['16名','4卓','決勝卓'] / 64人 → ['64名','16卓','4卓','決勝卓'] */
function ladderOf(size) {
  const out = [size + '名'];
  let n = size;
  while (n > 4) { out.push((n / 4) + '卓'); n = n / 4; }
  out.push('決勝卓');
  return out;
}
```

見せ方は横一列、あいだに細い矢印。最後の「決勝卓」だけ `--tk-accent` で光らせる。

`roundName()` は使わない——あれは「残り人数 → 回戦名」で、ここが欲しいのは卓数。

**渡すのは `prepared.field.length`**（`tier.size` ではない）。①の「N名」と
同じ数から作るので、二つが食い違いようがない。

## §6 入場の演出

### §6.1 出す条件

**三つとも満たしたときだけ。**

- `tier.stage` が `'title'` または `'final'`（＝タイトル戦・雀エイト選抜戦）
- `resume` が無い（復帰のときは出さない。続きを待っている人に演出を見せない）
- `prefers-reduced-motion` が `reduce` でない

### §6.2 中身

1.2秒。CSSアニメーションだけで、JSのタイマーで段を組まない。

- 見出し帯が上から落ちる（0.0s）
- 賞金と梯子が薄く浮く（0.25s）
- 自事務所の四人が左から順に立つ（0.45s から 0.09s ずつ）

**画面のどこかを触ったら即座に終端の状態へ飛ぶ。** `.tkRoot` に `.tkSkip` を付けて
`animation:none` にするだけでよい。

**そのために、地の状態＝終端の状態にしておくこと。**キーフレームが持つのは
「どこから来るか」だけで、`to` 側に何も書かない。`animation:none` にした瞬間に
要素は自分の素の見た目へ戻るので、それが終端でなければ演出を飛ばした人だけ
壊れた画面を見る。

**音は鳴らさない。** 出走表で `Sound.init()` を呼ぶと、
「卓に着く」で初期化するいまの一本道が二本になる。
iOS はマナーモードで黙るので、音を前提にした演出は端末によって別物になる。

### §6.3 調子（あれば）

`Office.condOf` があるときだけ、③のカードに小さく出す。
無い環境（単体ページ `taikai.html`）では**何も出さない**。既定値をここに書かない
——二か所に既定を持つと必ず片方が古びる。

**`st.cond` にその子の目が入っているときだけ出す。**`Office.condOf` は
知らない id に 0 を返すので、有無を見ずに出すと**まだ引いていない朝でも
全員が「ふつう」と言う。**自分（id 0）は `rosterOf` に入らないので、常に出ない。

## §7 顔の落とし方

```js
const faceOf = (c) => (c && c.id === 0
  ? `img/${c.face || 'p01'}.webp`
  : `img/${pad3(c.id)}.webp`);
```

`match.js` に同じ式がある。**写すこと自体はよいが、二本立て（自分は `p01`〜、
雀ドルは3桁）を崩さない。**片方だけ直すと自分の顔だけ出なくなる。

- `PORTRAIT_MAX_ID` は 200 で、`img/001.webp`〜`img/200.webp` は**全部ある**
  （074〜170 と 171〜200 は取り込み済み）。それでも `onerror` は外さない
  ——キャラを足したときに画像が一枚遅れることは必ずある
- `<img onerror="this.remove()">` で落とし、CSSの `--sil-img`（`ensureSilVar()` が入れる影絵）が下から出る
- `decoding="async"` を付ける
- **出す顔は七枚まで。** 768×1024 の webp なので、64人ぶん読むと数MBになる。
  全員一覧（⑤）には顔を出さない

## §8 触らないもの

- `prepare()` / `buildField()` / `makeTables()` / `runTournament()`
- `progressOk()` / `rebuild()` / `startResume()` / `abandon()`
  ——復帰の経路は出走表の**上**に乗っているだけで、下の作りとは無関係
- `.tkGroup` / `.tkGroupT` / `.tkNames` / `.tkName`（⑤はいまのまま）
- 対局の設定（`.tkSettings`）は大会選択の画面のもので、出走表には無い

**罠。** `renderField()` はテンプレート文字列一本で組まれている。
`.tkSetNote` のときと同じで、**中に逆引用符を入れると文字列がそこで切れる。**

**新しいクラスは全部 `tk` で始めること。** CSSはページ全体で一つの名前空間しかない。

## §9 段

一段ずつ、スクリーンショットで確かめてから次へ。

**段1 — 骨組み。** ①②⑤⑥だけ。賞金と梯子（§5）を出し、`data-tier`（§4）を三画面に付ける。
顔はまだ出さない。ここで**五つの大会を順に開いて、色と梯子が合っているかを見る**。
新人戦は「16名 → 4卓 → 決勝卓」、全国オープンは「64名 → 16卓 → 4卓 → 決勝卓」。

**段2 — 自事務所の四人（③）。** 顔・名前・段位・打ち筋・完成度バー。
画像は 001〜200 が全部あるので、**画像の取得を落として**影絵になることを見る
（Playwright の `route(..., r => r.abort())`）。

**打ち筋は必ず改行して段位の下へ。**折り返しに任せると、短い名前（「逆境型」）
だけが段位と同じ行に乗り、**四枚の完成度バーの高さが揃わない。**
バーと調子は `margin-top:auto` でカードの底に揃える——名前と打ち筋の行数が
一枚ずつ違うので、上から積むと同じものが四枚とも違う高さに出る。

**段3 — 注目の三人（④）。** `pickSpotlight()` を先に書き、`node tools/` で
「因縁が三人いるとき」「一人だけのとき」「一人もいないとき」を確かめてから画面に繋ぐ。

**段4 — 入場（§6）。** タイトル戦で出て、新人戦で出ないこと。
**大会の途中で落ちて「続きから」で戻ったときに出ないこと**を実機で見る。

段1〜3のあと `python3 build.py` が通ること。`index.html` は500KB以内。
この仕様で増えるのはCSSが3〜4KB、JSが3KBほどなので、余裕はある。

## §10 テスト

`node tools/test-taikai-field.js` … `ladderOf` と `pickSpotlight` の錠。
DOMに触らない関数だけを見る。

- `ladderOf` … 16人・64人・4人。**卓数が人数から出ていること**
- `pickSpotlight` … 因縁が三人／一人／ゼロ、自事務所を除くこと、
  `beaten` に入っている相手を因縁枠にしないこと、`recent` の順（新しい順）を守ること、
  同じ子を二度入れないこと、`field` の重複（`dup`）で二重にならないこと、
  強さが同じなら id で固定すること、`n` を超えないこと、
  `st` が空でも落ちないこと
- 本文の錠 … `root` の click が `button[data-tier]` で拾っていること（§4.1）、
  五つの大会ぶんの `--tk-accent` が `taikai.css` にあること、
  賞金が `--tk-accent` ではなく `--gold` で出ていること、
  ⑤が `prepared.field` を絞らずに回していること（§1 の「消さないこと」）、
  **組の先頭に来るクラス**が全部 `tk` で始まっていること
  （`.tkCond.cm2` のように `tk` の付いたクラスに重ねるのはよい——
  単独では効かないので他の画面へ漏れようがない。`office.css` と同じ作法）
