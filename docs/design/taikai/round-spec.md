# 回戦のあいだ — `docs/design/taikai/round-spec.md`

`src/taikai.js`（`runTournament` にフックを一つ足す／`mount` に画面を一つ足す）、
`src/taikai.css`、`shell.html`（釦の文言を一つ渡す）。
`prepare()` / `buildField()` / `makeTables()` / 控えの経路には触らない。

出走表のカード（`tkCard`。`field-spec.md` §2）を**そのまま使い回す**。
実機で崩れていないことは確認済み。

---

## §0 なぜ直すか

`playRounds()` が `runTournament` を最後まで回すので、
**`renderField()` が呼ばれるのは大会に入るときの一度きり。**
一回戦から決勝卓まで、あいだに画面が一枚も入らない。

`Match.play` が `host.remove()` した直後に、次の `Match.play` が `host` を作り直す。
遊ぶ側から見ると、「結果へ」を押した先が次の半荘の東1局になる。
**切れ目が無いのではなく、回戦という単位が画面に一度も出ていない。**

速さの設定は関係ない。最速だと一回戦から決勝まで数秒で終わるので症状が濃くなるだけで、
ゆっくりにしても見えるものは同じ。

`showResult` の釦が「結果へ」なのも、行く先が結果でないので嘘になっている。

---

## §1 決めたこと

- **一枚にまとめる。**「前の回戦の勝ち上がり」と「次の卓の顔ぶれ」を一画面に。
  二枚に割ると決勝までのタップが倍になる
- **一回戦の前にも出す。**出走表 →「卓に着く」→ 一回戦の卓 →「打つ」。
  ここで一枚挟んでおくと、決勝が**同じ儀式の続き**になる。挟まないと決勝だけが特別扱いになり、
  「いきなり始まった」感じが残る
- **自動処理と、控えから戻す回戦では出さない**
- **決勝卓だけ別の見せ方**にする

## §2 出す条件

**一つの文にまとめる。**枝を並べると必ず穴が開く。

> 出すのは、**自分の卓をこれから東1局から打つ回戦だけ。**

これで全部覆える。

| 場面 | 出るか | なぜ |
|---|---|---|
| 一回戦（自分が座る） | 出る | これから打つ |
| 準決勝・決勝卓（勝ち上がった） | 出る | これから打つ |
| 敗退したあとの回戦 | 出ない | 自分の卓が無い |
| 「自動で処理する」 | 出ない | 打たない（§2.1） |
| 控えから結果を戻す回戦 | 出ない | もう打ち終わっている |
| 対局の途中から戻る（`Resume`） | 出ない | 東1局からではない |
| 自分が出ていない決勝卓 | 出ない | 自分の卓が無い |

### §2.1 自動処理の見分け

`autoMatch` のとき `playRealMatch` は**在るが何も返さない**（`taikai.js` の既存の注記）。
`runTournament` からは区別できないので、**`playRounds()` の側で決める**——
`st.autoMatch` が真、または `store.playRealMatch` が無いときは
`onRoundStart` を**渡さない**。渡さなければ何も起きない。

### §2.2 対局の途中から戻る場合

`resumeFor(t)` は `saved` を**一度きり**で消費する。
中継の判定でこれを呼ぶと控えが消えて、本来の復帰が死ぬ。

**覗くだけの関数を別に足すこと。**

```js
/* 消費しない。中継を出すかどうかの判定にだけ使う */
const hasSavedFor = (t) => !!saved && sameSeats(saved.seats, idsOf(t));
```

## §3 フック

`runTournament` の `opts` に一つ足す。`onProgress` と同じ「渡さなければ何もしない」口。
**`while` の中身の順序は変えない。**

```js
opts.onRoundStart?  … async (info) => void。待つ。無ければ何もしない
```

呼ぶ場所は**二か所**。どちらも「卓割りが決まって `push()` した直後、卓を打ち始める前」。

1. `while` の中、`push()` の次の行
2. 決勝卓の `push()` の次の行

ここなら**前の回戦の結果（`rounds` にもう入っている）と次の卓の顔ぶれの両方が揃う。**
これより前だと卓が無く、これより後だと打ち始めてしまう。

`info` に入れるもの：

```js
{
  ri,                       // 回戦の番号（0から）
  name,                     // roundName(alive.length) か '決勝卓'
  size,                     // この回戦の残り人数
  isFinal,                  // 決勝卓か
  table,                    // 自分が座る卓の4人。**自分がいなければ null**
  prev,                     // 前の回戦（rounds の最後）。一回戦では null
  alive,                    // 残っている全員（人数を出すため）
}
```

`table` が `null` なら**画面側が黙って返す。**判定を二か所に書かない。

`await` するので、控え（`prog`）は**すでに書き終わっている**。
中継を見ている最中に閉じられても、卓割りは残り結果は空なので、
復帰したときに §2 の規則でもう一度出る。それでよい。

## §4 画面（通常の回戦）

```
① 見出し      準決勝                    ← --tk-accent（大会の色）
② 勝ち上がり  あなたの事務所：3人が残りました
              ○○ ／ ××（一回戦敗退）…
              残り 16名
③ 次の卓      tkCard ×4                 ← 自分は縁が金
④ 釦          準決勝を打つ
```

**②は一回戦では出さない。**前の回戦が無い。①③④だけの軽い画面になる。

### ② 勝ち上がり

自事務所の四人だけを見る。**64人ぶんの勝敗は出さない**——読む画面ではない。

- 残った子は名前だけ
- 落ちた子は `prev` から着順を引いて「○○（一回戦・2位）」
- 最後に「残り N名」

**自分が落ちたことはここに出ない**（自分が落ちたら §2 でこの画面自体が出ない）。

### ③ 次の卓

`tkCard` を4枚。順序は**自分が先頭**、あとは `table` の順。
`cardHTML(c, { mine: c.id === 0 })` をそのまま呼ぶ。

**見出し語（`why`）は付けない。**出走表の「優勝候補」「前に当たって、勝てなかった相手」は
出走表の文脈のもので、ここでは意味が変わる。

### ④ 釦

文言は `${name}を打つ`。決勝卓だけ §5。

## §5 決勝卓

同じ骨格のまま、**四つだけ変える。**

- 見出しを大きく、`--tk-accent` を効かせる
- 顔を大きく（`.tkBridge.final .tkFace`）。四人を横一列に
- 賞金を再掲する（`優勝 3,000,000円`）。出走表で見たきり、ここまで一度も出ていない。
  **梯子は出さない**——ここが最後なので、もう先が無い
- **カードを「顔が主、文字が従」に組み替える**（§5.1）

釦は「**決勝卓へ**」。

②の勝ち上がりは決勝でも出す。ここが一番効く——
四人で入って一人だけ残った、が読める唯一の場所になる。

### §5.1 顔が主、文字が従

通常の中継の `tkCard` は 顔・名前・級・打ち筋・完成度バー が縦に積まれ、
顔は上半分だけ。決勝では**顔をカードいっぱいに使い、名前と級は顔の下端に重ねる。
打ち筋と完成度バーは出さない。**

ここまで三回戦を打って来た相手なので、能力の数字はもう要らない。
**残った三人が誰かだけが要る。**

**実装は `tkCard` の使い回しのまま、`.tkBridge.final` の CSS だけで組み替える。
`cardHTML` に分岐を増やさない**——出走表と中継と決勝で三通りのカードを組むことになり、
直すたびに三か所を見ることになる。`tools/test-taikai-round.js` が
「`cardHTML` が見る opts は `mine` と `why` だけ」を錠にしている。

急所：

- **名前は絶対配置にしない。**`margin-top:auto` で下端へ寄せる
  ——絶対配置だと、名前が二行になったときに級と重なる
- **A の `tkBare`（縦中央）は決勝では効かせない。**顔の下端に重ねるので、
  真ん中へ寄せると顔の中に浮く。消すのは**級の下の `auto` だけ**
  （名前の `margin-top:auto` は決勝でも同じものが要る）
- **膜を一枚敷いてから字を載せる。**明るいポートレートでは、字だけ置くと沈む。
  膜に加えて**四方に1pxの暗い影**（ホワイトボードの字と同じ手）——
  ぼかしだけだと、白い服や明るい壁のところで輪郭が消える。
  下帯がいちばん明るい四枚（`098` `161` `089` `181`）で確かめること
- **字は詰める。**13px だと4列（1枚 89px）で六文字の名前が折れて
  「テスト事務／所」になった

## §6 `showResult` の釦

いまは「結果へ」で固定。行く先は次の半荘なので嘘になっている。

`match.js` の `showResult` に文言を外から渡す口を足し（既定は `'結果へ'`。
練習対局や雀荘の呼び出しは触らない）、`shell.html` の `playRealMatch` が
`ctx.isFinal` を見て渡す。

- 通常の回戦 … `次の回戦へ`
- 決勝卓 … `結果へ`

**`ctx` にはもう `isFinal` が入っている**（`runTournament` が決勝卓の
`playRealMatch` に渡している）。新しく数えない。

## §7 罠

**`data-tier` を持つ要素をこの画面に置かないこと。**
`root` 自身が `data-tier` を持つので、`click` の拾い口は `button[data-tier]` に
狭めてある（`field-spec.md` §4.1）。ここに `data-tier` の釦を作ると同じ穴が開く。

**釦は専用の `data-act` にする。**`start` / `result` / `back` / `resume` /
`abandon` はすべて別の処理に繋がっている。`data-act="round-go"` を新しく足し、
フックが持っている解決関数を呼ぶだけにする。

**解決関数は一つしか持たない。**二回目の回戦に入るときに前の回戦の解決関数が
残っていると、押していないのに進む。渡す前に必ず捨てる。

**`body.inMatch` が外れていること。**`Match.play` は自分で外してから返すので
通常は問題ないが、外れていないと `#view` が隠れたままで**画面が真っ暗になり、
タップの当たり所も無くなる**（進めなくなる）。段2の実機確認で必ず見る。

**「最初からやり直す」を中継に出さないこと。**`#appReset` は `shell.html` が
**全画面に出している枠**で、`taikai.js` の持ち物ではない。隠しているのは
表紙（`body.onTitle`）と対局中（`body.inMatch`）の二つだけなので、
何もしなければ中継にも出る。**「打つ」の隣に、押すと大会が消える釦を置かない。**

**`#nav`（下のタブ）も同じように隠す。**残すと答えずに抜けられ、
**解決されない `runTournament` が控えを抱えたまま残る。**遊ぶ側は
「続きから」で入り直した別の走行を見ることになり、動きはするが二重になる。
`body.inMatch` が nav を隠しているのと同じ扱いにする。入口を塞ぐほうが安い。

`body.tkHold` を立てて `shell.html` の側で隠す——**印を立てるのは `taikai.js`、
何を隠すかを決めるのは `shell.html`**（枠は向こうの持ち物なので、
中身をこちらから知らない）。落とすのは二か所：

- `showLoading()` … 中継を出て卓に入るとき
- `shell.html` の `go()` … **画面を出たとき。ここが最後の砦**

**nav を消したら、そのぶんの下の余白（`#scroll` の `padding-bottom:64px`）も消すこと。**
残すと画面の底に 64px の空白が出る（表紙が `body.onTitle #scroll` で同じことをしている）。

**中断の出口は新しく作らないこと。**中継から出られるのは「打つ」だけで、
やめる道はもうある——リロード → 表紙の「続きから」→ 出走表 →「この大会を諦める」。
`tools/test-taikai-round.js` が「中継の押せる口は `round-go` 一つだけ」を錠にしている。

**新しいクラスは全部 `tk` で始める。**CSSはページ全体で一つの名前空間。

**`renderField` のテンプレート文字列と同じで、中に逆引用符を入れない。**

### §7.1 決めたこと（実機で見て確定した。蒸し返さない）

- **出走表の `#appReset` は残す。**アプリ全体の備品だと分かった以上、
  出走表だけ消すのは不整合。中継で危なかったのは**位置**の問題で、
  出走表は下に一覧が続くので「卓に着く」から十分離れている。
  **`tkHold` を立てるのは中継だけ**
- **`PORTRAIT_MAX_ID` はカードと無関係。**読んでいるのは `title.js` の表紙の
  敷き詰めだけで、カードの顔は `faceOf` が id から直に組む（`field-spec.md` §7）。
  いまは 200 で `img/001.webp`〜`200.webp` も全部ある
- **④の見出し語は文字だけで足りる**（`field-spec.md` §3 の `top`）。
  色や大きさは足していない。実機で見て、足りなければそのとき足す

## §8 これで見えるようになる粗

**16人の大会は、一回戦の名前が「準決勝」になる。**
`roundName()` は残り人数から引くので、`roundName(16)` は `'準決勝'`。
新人戦と地方リーグは「準決勝 → 決勝卓」の二回戦で、**いきなり準決勝から始まる。**

いままで回戦名がほとんど画面に出ていなかったので誰も気づかなかったが、
中継画面を入れると最初に出る。

**今回は直さない。**直すなら `roundName()` を「残り人数」ではなく
「あと何回戦か」から作り直すことになり、`runTournament` と控えの両方に触る。
`docs/BACKLOG.md` に一行。着手条件は「16人の大会の回戦名が実機で気になったら」。

## §9 段

**段1 — フックだけ。**`onRoundStart` を足し、`playRounds()` から
「何もしない関数」を渡す。画面は作らない。
既存のテスト（`test-taikai-*` / `drive-taikai-resume`）が全通過することを確認。
`onRoundStart` を渡さないときに**一行も挙動が変わらない**ことがここの検品。

**段2 — 通常の回戦（§4）。**一回戦と準決勝で出ること。
`autoMatch` を「自動で処理」にすると**出ないこと**。
自分が一回戦で落ちたあと、準決勝と決勝卓で**出ないこと**。

**段3 — 決勝卓（§5・§5.1）。**顔がカードいっぱいになること、
打ち筋と完成度バーが出ないこと、賞金が再掲されること、釦が「決勝卓へ」。
**実機で見るのは一点——背景の明るいポートレートで名前が沈んでいないか。**
沈んでいたら顔の下に出す形へ戻す。

**段4 — 釦の文言（§6）。**通常の回戦で「次の回戦へ」、決勝卓で「結果へ」。

**実機で見るもの**（段2のあと）：

1. 一回戦の前に一枚出て、「打つ」で東1局に入る
2. 対局が終わって「次の回戦へ」→ 中継 →「準決勝を打つ」
3. **中継を見ている最中にリロード** → 表紙 →「続きから」→ 出走表 →「続ける」。
   その回戦の中継が**もう一度出て**、卓割りが変わっていないこと（§3）
4. 対局の**途中で**リロード → 復帰したときに中継が**出ない**こと（§2.2）
