# 対局画面の作り直し

置き場所: `docs/design/match/spec.md`
関連: `src/game.js` / `src/ui.js` / `src/match.js` / `src/match.css` / `src/serifu.js` / `src/taikai.js`
モック: `docs/design/match/table-mock.html`（色と数値はここから写す）

---

## 0. 方針

対局画面はこの作品の中心。ここが凡庸なら他が何をしても意味がない、という前提で作る。

麻雀のUIの出来を決めているのは三つある。**音・牌の動き・卓の絵**、この順で効く。
絵から入ると「小綺麗」までしか行かない。**音と動きを先に入れる。**

### 着手前に必ず読むもの

- `docs/HANDOVER.md` — architectural truth。ソースから推測しないこと
- `src/match.css` の全文 — §4 の前提が今も正しいか確認する

### 現状で確認済みのこと（2026-09-04）

- **音が一つも入っていない。**`Audio` も `AudioContext` もソース全体に存在しない
- `UI.render()` は毎回 `innerHTML` を全書き換えしている。同じ牌が動く表現は作れない
- `body.inMatch #center{display:contents}`、`#table` は `flex-direction:column`。
  **四人卓ではなく、下家→対面→上家→自分を縦に積んだ列レイアウト**
- `body.inMatch .tile{overflow:hidden}` — §5 でここを動かす
- `Game` のコンストラクタが `this.dealer = 0`。プレイヤーは常に起家
- `onTileClick()` は一度目で選び二度目で切る二段構え

### 段の順番

| 段 | 内容 | 触るファイル |
|---|---|---|
| 1 | 起家のランダム化と自風表示 | `game.js` `ui.js` |
| 2 | 音 | `sound.js`（新規） `ui.js` `taikai.js` `build.py` |
| 3 | 牌のkeyed化と移動（**現行レイアウトのまま**） | `ui.js` |

動いている画面の上でDOMの土台を入れ替え、それが通ってから卓を建て替える。
同時にやると、壊れたときにどちらが原因か切り分けられなくなる。

## 1. 起家のランダム化と自風表示

### 1.1 なぜ

`this.dealer = 0` で固定されているため、プレイヤーが必ず東家から始まる。
席順そのものは `tournament.js` の `makeTables()` が既に混ぜていて、
`match.js` がプレイヤーを添字0へ回転させている。
**固定されているのは親が誰から始まるかだけ。**

### 1.2 game.js

コンストラクタの `this.dealer = 0;` を置き換える。

```js
/* 起家。指定が無ければ毎回振り直す。席順（誰が下家か）は
   makeTables() が既に混ぜているので、ここで親を回せば
   「自分が必ず東家」だけが消える。
   opts.startDealer はリプレイ検証と席決め演出のために残してある */
this.dealer = (opts.startDealer !== undefined)
  ? ((opts.startDealer % 4) + 4) % 4
  : Math.floor(Math.random() * 4);
this.startDealer = this.dealer;
for (const p of this.players) p.jikaze = 27 + ((p.seat - this.dealer + 4) % 4);
```

最後の行は保険。`players` は全員 `jikaze: 27` で作られ、実際の値が入るのは
`deal()` の中。いまは `deal()` より前に描画が走らないので実害はないが、
親が0でなくなると「東が二人いる」状態を一瞬でも見せる危険が出る。

`nextKyoku()` は `kyoku` と `dealer` を別々に持っているので無改修で回る。

### 1.3 ui.js — 自分の自風を出す

**同じコミットに入れること。** 他家には `oppKaze` で自風が出るが、
**自分の自風はどこにも出ていない。**常に東だったから要らなかった。
片方だけ入れると「自分が何家か分からない」画面になる。

`render()` の `#info` の `.scores` に自風を足す。

**罠**: `const KAZE_CH` は `$('#info').innerHTML = ...` の**後ろ**で宣言されている。
そのまま `#info` のテンプレート内で使うと TDZ で落ちる。
**宣言を `render()` の先頭へ移してから使うこと。**

### 1.4 確認

対局を10回始めて東一局の親が四人にばらけること。
自分が親でない局で自分の自風が出ていること。

## 2. 音

**費用対効果で一番大きい。** 麻雀は「牌を置く」物理動作のゲームなので、
音がないと打っている感触が出ない。卓の絵を作り込むより先に効く。

### 2.1 音源

**他所のゲームから採らないこと。** `tiles/` が CC0 の素材を使って
`tiles/LICENSE.txt` に出典を書いているのと同じ扱いにする。
CC0 の効果音を集めるか、実際に牌を録る。
`audio/LICENSE.txt` に出典を必ず残すこと。

必要なのは9つ。すべて0.1〜1.5秒の短いもの。

| 名前 | 場面 | 備考 |
|---|---|---|
| `discard` | 打牌 | 一番よく鳴る。ここの質が全体を決める |
| `draw` | ツモ | `discard` より小さく、軽く |
| `call` | ポン・チー・カン | |
| `riichi` | リーチ宣言 | 棒が転がる音を含めてよい |
| `agari` | ツモ・ロン和了 | 一番派手にしてよい |
| `deal` | 放銃（自分が振った） | `agari` とは別に、沈む音 |
| `dora` | ドラめくり | |
| `ryuukyoku` | 流局 | |
| `tap` | ボタン | 対局以外でも使う |

### 2.2 実装 — `src/sound.js`（新規）

WebAudio を使う。`AudioBuffer` に decode して持つ。
`new Audio()` の使い回しは打牌の連打で遅延と取りこぼしが出る。

```
Sound.init()        AudioContext を作る（ユーザー操作の中で呼ぶこと）
Sound.load()        9つを decode して持つ。失敗しても対局は続ける
Sound.play(name)    鳴らす。未初期化・音量0なら黙って何もしない
Sound.volume(v)     0〜1
```

**必ず守ること**

- **`AudioContext` は一つだけ。**対局ごとに作ると端末が音を出さなくなる
- **初期化はユーザー操作の中で。**iframe の自動再生制限がある。
  `taikai.js` の「卓に着く」ボタン（`data-act="start"`）が自然な解除の口
- **読み込みに失敗しても対局を止めない。**音は無くても打てる
- **`discard` は `playbackRate` を毎回 ±3% 振る。**
  同じ音が17回続くと機械音に聞こえる
- **`UI.speed === 0`（早送り）のときは鳴らさない。**
  おまかせの早送りで全部鳴ると音の壁になる。
  `UI.speed < 200` を目安に打牌音を間引く

### 2.3 呼ぶ場所 — **`ui.js` からだけ**

**`game.js` には一行も足さないこと。** `game.js` は Node の経済シミュレーションから
呼ばれていて、`Sound` を参照した瞬間にヘッドレスで落ちる。

音は全部 `io` 層で鳴らす。`game.js` は既に `this.io.event(text, ms, who)` と
`this.io.result(data)` で「誰が・何を」を渡してきているので、
`UI.event()` と `UI.result()` の中で分岐すれば足りる。

打牌は `UI.render()` ではなく **`UI.resolve()` と段3の差分検出**から鳴らす
（`render()` は何度も呼ばれるので、そこで鳴らすと連打になる）。

### 2.4 設定

`taikai.js` の「対局の設定」に音量の行を足す。
`進む速さ` `補助表示` と同じ `data-set` の仕組みに乗せる。
保存は `st.sfxVolume`。**`undefined` のとき既定値に落ちること**を必ず確認する。
古いセーブが壊れてはいけない（前方互換はこの作品の最優先事項）。

### 2.5 build.py

`src/sound.js` を読み込み対象に足す。`audio/` は ZIP に含める。
`index.html` の500KB制限は `index.html` にしかかからないので、
音源のサイズは問題にならない。

### 2.6 確認

音量を最大・中・0の三通りで一局ずつ。0のときに完全に無音になること。
おまかせの最速で音が壊れないこと。

## 3. 牌のkeyed化と移動

**現行レイアウトのまま入れる。卓の作り直しより先。**

### 3.1 なぜ

`render()` が毎回 `innerHTML` を全書き換えしているので、
「同じ牌が動く」表現が原理的に作れない。雀魂を触って気持ちいいのは
卓の絵ではなく牌が動くからで、ここが手触りの本体になる。

### 3.2 範囲を絞る

**`render()` 全体を作り直さない。** key が要るのは牌だけ。
席プレートも中央の情報も吹き出しも、今までどおり `innerHTML` で組み直してよい。

keyed にするのは五つのリストだけ。

- `#handrow`（自分の手牌）
- `#river-bottom` / `#river-right` / `#river-top` / `#river-left`（四つの河）

他家の手牌（`.backs`）は裏牌が並ぶだけで個体差がないので、
枚数が変わったときに増減させるだけでよい。**keyed にしなくてよい。**

### 3.3 キー

牌のidは 0〜135 で既に一意。`data-id` に入れる。
`Map<tileId, HTMLElement>` でノードを持ち、描画のたびに
「あるべきidの並び」と突き合わせて、あるものは使い回し、
無いものだけ作り、余ったものだけ外す。

### 3.4 移動のさせ方

**自分の打牌は FLIP。** ノードを使い回しているので、
手牌から河へ `append` する前に `getBoundingClientRect()` を取り、
移した後にもう一度取って、差分ぶんだけ逆向きの `transform` を当ててから
0へ遷移させる。同じノードが動くので、これが一番自然に見える。

**他家の打牌は飛ばし込み。** 他家の手牌は裏なので、移動元のノードが無い。
河に新しく作ったノードに、その家の手牌のあたりからの `transform` を初期値として当て、
0へ遷移させる。

**必ず守ること**

- `render()` は `io.update()` から何度も呼ばれる。
  **前回のid列と比べて、実際に変わったときだけ動かすこと。**
  毎回の描画で animation を仕掛けると画面が痙攣する
- `UI.speed === 0`（早送り）と `prefers-reduced-motion` のときは
  **アニメーションを完全に飛ばす。**位置だけ即座に確定させる
- 局が変わると河が空になる。そのときは飛ばさず、そのまま消す

### 3.5 音との合流

段2の `discard` / `draw` はここで鳴らす。
**差分検出で「河に牌が増えた」ことを検知した瞬間**に鳴らすのが正しい。
アニメーションの開始と音の頭を揃えること。ここが数十ms ずれると気持ち悪い。

### 3.6 確認（録画）

- 自分の打牌、他家の打牌、鳴き、リーチ、和了を含む一局を**録画**して出すこと。
  この段は静止画では確認できない
- おまかせの最速で一半荘。画面が痙攣しないこと
- 局をまたいでノードが漏れていないこと（`Map` のサイズが際限なく増えないこと）

## 4. 四人卓レイアウト

### 4.1 何が変わるか

現行の縦一列を四方に人を置く卓に戻す。
`#center{display:contents}` を外す。`match.js` の `TABLE_HTML` は既に
この構造を持っているので、**HTMLは基本そのまま使える。変えるのはCSS。**

`#table` の `overflow-y:auto` は捨てる。`fitTable()` / `clampTableScroll()` は
§7 まで残し、段7が済んでから不要なぶんを消す。**段4では消さないこと。**

### 4.2 卓の作り

- 卓は正方形。画面の高さから手牌ぶんを引いた残りに収まる辺長。
  **上端が切れないことを必ず確認する。**モック初版は卓が大きすぎて
  対面の手牌が画面外に出ていた
- 立体は `#center` を包む要素に `perspective`、卓面に `rotateX(36deg)`。
  canvas ではないので PLiCy の制約に触れない
- 色はモックのターコイズ。緑卓にしないこと。立ち絵が写実なので、
  雀魂のアニメ調の配色に合わせると立ち絵だけが浮く
- 卓面と部屋に網点、縁に黄色い枠と黒い輪郭。
  **ポップに見えているのは色ではなく輪郭と網点。**
  牌にも席プレートにも黒い縁を回し、影はぼかさず真下にずらす
- 牌の寸法はモックの固定pxではなく、`match.css` が既に持っている
  `--tw` / `--rw` の仕組みに乗せ直すこと

### 4.3 河と手牌の位置決め — ここが一番間違えやすい

**端（`left` / `right`）で位置を決めてはいけない。**
`right:8px` は回転する**前**の箱に効く。牌13枚の細長い行を中心まわりに90度回すと、
箱は縦長に変わるのに中心は動かないので、行の長さの半分だけ内側へ引き込まれる。
**左右の家だけずれて対面は正しく見える**、という分かりにくい壊れ方をする。

**中心に置いた点を回して外へ押し出す。** そのうえで河と手牌で基準を変える。

- **河は内側の端を固定する。** 局が進むと1段から3段へ伸びるので、
  中心を基準にすると内側の端が局の途中で動く。
  ゼロサイズの点を回して外へ出し、そこから外向きに伸ばす
- **手牌は中心を基準にする。** 鳴くと13枚から10枚、7枚と減るが、
  辺の中央に揃っていてほしい

同じ見た目の壊れ方をするが、**何が動いてほしくないかが違うので答えが違う。**
片方に合わせて両方直すと、必ずどちらかが局の途中でずれる。

### 4.4 中央のコンパス

中央のプレートに 局・本場・残り枚数・ドラ表示、その四辺に各家の自風を丸で置く。
親は黄色、自分は差し色。§1.3 の自風と二重になるが、**両方出すこと。**
片方だけだと見落とす。

### 4.5 席プレート

四辺に名前・自風・点数・丸い顔写真。顔は `img/` の実物。
元画像は 768×1024 で顔は上から15%前後なので `object-position:50% 14%` あたり。

**自分の席プレートだけ色を反転させる。** 起家がランダムになると
「自分がどれか」を探す一瞬が生まれるので、そこを潰す。

### 4.6 確認（スクリーンショット必須）

静止画で見つからない種類のずれがあるので、次の3枚を必ず撮ること。

1. 配牌直後
2. **誰かが鳴いた直後**（手牌の枚数が変わる）
3. **河が3段に伸びた終盤**（河の長さが変わる）

2と3で、左右の家の手牌と河が卓からずれていないこと。
あわせて、段3の移動アニメが新レイアウトでも正しく飛ぶこと（録画）。

## 5. 牌の厚み

麻雀牌は幅21mm × 高さ28mm × 奥行17mm。奥行が幅の8割ある。
薄く描くとカードに見える。特に立っている他家の手牌が板に見える。

見える面は二つだけなので、その二つだけ作る。

- **立っている牌（他家の手牌）**: 上面が奥へ伸びる。
  `bottom:100%` に面を置き、`transform-origin:center bottom` で `rotateX(90deg)`。
  手前は背面なので、上面も手前がオレンジ、奥ほど象牙色
- **寝ている牌（河）**: 手前の面が卓へ落ちる。
  `top:100%` に置き、`transform-origin:center top` で `rotateX(-90deg)`。
  面が象牙、胴がオレンジ
- **自分の手牌**: 3D空間の外なので影を積む。
  `box-shadow` に `0 6px 0 var(--back-a)` を挟み、象牙の面の下に胴を覗かせる

`box-shadow` でごまかすと、左右の河は90度回っているぶん影が横向きに出て破綻する。
**河と他家手牌は必ず3Dの面でやること。**

### 5.1 既存CSSとの衝突

`body.inMatch .tile{overflow:hidden}` が今ある。このままだと厚みの面が切られる。
**`overflow:hidden` を `.tile` から外し、`.tile .face`（内側のimg）側へ移すこと。**
外した結果 SVG の図柄がはみ出すようなら、`.face` を包む要素を一枚増やす。

`transform-style:preserve-3d` は親から途切れると効かない。
**`#center` から牌までの経路に `overflow:hidden` や `filter` を挟まないこと。**
挟んだ瞬間に3Dが潰れ、厚みだけが平らな板として貼り付いた妙な絵になる。

### 5.2 数値

厚みはCSS変数（`--th`）で出し、実機を見て詰める。
モックは他家11px・河9pxだが、**卓の傾きを変えたら必ず見直す。**

## 6. セリフのカットイン

### 6.1 何を変えるか

現行の `#tachie` は四人の顔を小さく並べ、喋った人だけ大きくする作り。
これを**上の角に出るカットイン＋吹き出し**に置き換える。
卓の左右には帯が余るので、写真はそこに完全に収まる。河にも手牌にもかからない。

- 左側の席（上家・自分）は**左上**、右側の席（下家・対面）は**右上**
- 吹き出しのしっぽは**カードを向く**（漫画の作法どおり）
- 同時に、喋った人の**席プレートを光らせる**
- 誰が喋ったかは写真・名前・席プレートの三つで分かる
- リーチ・ツモ・ロンのときは吹き出しの地を差し色にする
- カードは左右で反転させる。左上は左に傾いて影が右下、右上は右に傾いて影が左下、
  テープの位置も外側。これがないと右上で「左から貼られた紙」に見える

### 6.2 ui.js

- `initTachie()` は不要になる
- `renderTachie()` は「時間切れで引っ込める」処理だけ残す
- `match.js` の `UI._tachieSeat` / `_tachieReady` の後始末は新しい状態名に置き換える。
  **残っていると次の対局に前の顔が出る**ので、消すのではなく置き換えること

**`SERIFU` 側は一行も触らない。** `chara` 19種を鍵にする仕組みも場面11種もそのまま。
表示方法だけの変更。

### 6.3 引っ込める条件

**現行の「捨て牌4枚ぶん」をそのまま使う。**
時間ではなく捨て牌の数で測るので、早送りでも自分の手番でも同じだけ残る。
よく出来た設計なので置き換える理由がない。

### 6.4 頻度

カットインが河を隠さなくなったので、**`idle`（雑談）でも出してよい。**
出現率18%のまま、全場面でカットインを出す。

## 7. 縦持ちの扱い

### 7.1 強制横持ちはできない

`screen.orientation.lock()` はフルスクリーン中でないと効かず、
iOS Safari は非対応、PLiCy は iframe なのでフルスクリーン権限も取れない。
`match.js` の既存コメントの結論が正しい。**ここは変えない。**

### 7.2 回転表示を足す

ラッパーに `rotate(90deg)` をかけて幅と高さを入れ替える。
**OS側の画面回転ロックを入れているユーザーにも横画面を届けられる**のが利点。
今の作りだと「横にしてください」と言われても物理的にできない人が一定数いる。

**強制ではなくトグルにすること。** 持ち方を変えていないのに画面が横倒しになると、
ユーザーは普通にバグだと思う。

### 7.3 必須作業

`#overlay` / `#toast` / `#rotateHint` は `position:fixed` で `document` 直下にいる。
**回転ラッパーの内側へ移すこと。** 外にいると一緒に回らない。

### 7.4 縦のまま打つ道は残す

回転はトグルなので、回転しない人には**現行の列レイアウトを残す。**
`@media(orientation:portrait)` で `flex-direction:column` を維持し、
横持ちと回転表示のときだけ四人卓にする。

**列レイアウトを消さないこと。**縦で打ちたい人の唯一の道になる。
段3の移動アニメは列レイアウトでも動くはずだが、**縦でも必ず録画で確認すること。**

## 8. 打牌の手触り

`onTileClick()` は一度目で選び二度目で切る二段構え。
誤打を防ぐ設計として理にかなっているが、一局17回やると
打っているというより確認作業をしている感覚になる。

`taikai.js` の「対局の設定」に **`打牌の操作`** を足す。

- **`一度押し`（既定）** — 押した牌をそのまま切る
- `二度押し` — 現行の動き
- 上へスワイプは**どちらの設定でも常に有効**にする

既定を一度押しに変えるのは、段2の音と段3の牌の動きが入っていれば
「切った」ことが十分に伝わるため。**段8は段2と段3が済んでから入れること。**
順番を前後させると、手応えの無いまま誤打だけが増える。

保存は `st.discardMode`。`undefined` のとき既定値に落ちること。

**追記（2026年9月5日・実機で打って直した）。**`一度押し` の中身を
「押した瞬間に切る」から**「離した瞬間に切る」**へ変えた。

実機で**指の接地が 9〜10mm あり、牌幅より広い**ことが分かった
（横持ち43px／SE 30px／縦持ち26px）。当たり判定を広げても隣が狭くなるだけで直らない。
問題は判定の広さではなく、**離した瞬間に初めて何を切ったか分かること**だった。

    pointerdown … 指の下の牌が持ち上がる（切る前に何を掴んだか見える）
    pointermove … 持ち上がる牌が指の下の牌に追随する（横へずらせば直せる）
    pointerup   … そのとき持ち上がっている牌を切る
    帯の外で離す … 取り消し
    上へ払う     … いままでどおり即座に切る

**一動作で切れる手触りは変わらない**（iOS のキーボードと同じ仕組み）。
`single` / `double` の関係も変えていない——`double` は「押している間は選び直せる」が
乗るだけで、確定はいままでどおり二度目。確認は `node tools/check-hand.js`。
