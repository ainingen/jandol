# 和了画面の作り直し

置き場所: `docs/design/match/agari-spec.md`
関連: `src/ui.js` / `src/match.js` / `src/match.css`
前提: `docs/design/match/spec.md` の8段が完了していること

## 0. なぜ作り直すか

卓・牌・音を全部作り直したのに、**局が終わるたびに必ず出る画面だけが古いまま**になっている。
一局ごとに見る面なので、残っている中でここが一番目に付く。

現状の問題は五つ。すべて同じ原因から出ている。
**この画面が「点数の集計表」として作られていて、「局が終わった瞬間」として作られていない。**

1. **感情の向きが逆なのに画面が1ピクセルも違わない。**
   自分が3900和了った画面と、自分が12000振り込んだ画面が、同じ金枠・同じ金の見出し・
   同じ位置。しかも放銃のほうが数字が大きいので、**負けたほうが派手に見える**
2. **一番顔を出せる瞬間に、顔を隠す箱を置いている。**
   立ち絵とカットインが箱に切られている
3. **卓が完全に消える。** 箱が横幅の6割、縦では画面の4割を占め、
   誰の河に当たり牌が並んだかが、結果を見ている間ずっと見えない
4. **縦で箱が中央からずり下がっている**
5. **流局が支払い後の点数を並べているだけで、誰が誰に払ったか分からない**

### 実装前に確認済みのこと

- **`ui.js:733` の `UI.gameOver` は死んでいる。**785行目の
  `UI.gameOver = async function (rank) { this._lastRank = rank; };` で上書きされている。
  実際に出ているのは `match.js:373` の `UI.modal`
- `data` には `winner` `loser` `hand` `melds` `winId` `doraIndicators` `uraIndicators`
  `result` が来ている。**四分岐の判定に `game.js` へ足すものは無い**

## 1. 四つに分ける

一つの画面の色替えではなく、**四つの別の画面**として設計する。

| | 点棒の流れ | 主役 | 送り |
|---|---|---|---|
| **自分がツモ** | 3人 → 自分 | 自分 | タップを待つ |
| **自分がロン** | 1人 → 自分 | 自分。振り込んだ相手も出す | タップを待つ |
| **自分が振り込み** | 自分 → 1人 | **和了った相手** | タップを待つ |
| **他家同士** | 1人 → 1人 | 和了った人 | タップを待つ |

**四分岐すべてタップを待つ。**自動で送るのは、おまかせ（`giveUp`）と
最速（`speed === 0`）のときだけ——そこは人が見ていない。

> **他家の和了も自動で送らないこと。**他家のツモでは自分が払っており、
> 誰が何で上がったかは順位にも打ち方の読みにも効く。
> 初版で `other` だけ自動送りにしたが、実機で「何が起きたか分からない」となった（2026年9月5日）。

**送るのは帯のどこでもタップ。**釦は置かない（横持ちのスマホで小さな釦を狙わせない）。
一度目で演出を確定、二度目で送る。**演出が終わってから「タップで次へ」を出す**
——押せると分からなければユーザーは待つだけになるが、演出中に出すと、
まだ動いているのに押させることになる。

## 2. 一番大きい数字を変える

**これが1の問題の解です。**

いま一番大きく出ているのは「和了った人の点数」。だから12000振り込んだときに
12000が大きく出て、派手に見える。

**一番大きい数字を、常にプレイヤー自身の増減にする。**

- 自分がツモ → **+3900**（金）
- 自分がロン → **+3900**（金）
- 自分が振り込み → **−12000**（差し色。赤系）
- 他家同士 → **±0** か **−2000**（ツモ被り。目立たない灰）

和了った人の合計点は**二番目**に落とす。プレイヤーが知りたいのは
「自分がいくら動いたか」であって、他人の点数ではない。

符と翻は三番目。**大きさの順が、そのまま関心の順になっていること。**

---

## 3. 卓を消さない

箱で覆うのをやめる。**卓は最後まで見えていること。**

### 上半分（卓）はそのまま残す

- 河はそのまま。**ロンの当たり牌は、振り込んだ人の河で光らせる**
  （誰の何に当たったかが、その場で見える）
- **和了った人の手牌を、卓の上で表向きに倒す。**段3のkeyed化と段5の厚みが
  そのまま使える。他家の裏牌がその場でめくれる
- 席プレートはそのまま。点数が動くのはここ（§5）

### 下半分に情報を置く

自分の手牌があった帯を使う。箱を作らず、**帯として置く。**

- **和了手を大きく並べる**（誰が和了ったかに関わらず、読める大きさで）。
  和了牌は少し離して、光らせる
- 副露は右端にまとめる
- ドラ表示と、リーチしていたなら裏ドラ

### 立ち絵は主役の側に大きく

**カットインの枠を流用せず、専用の大きさで出す。**カットインは会話の演出で、
こちらは局の締めなので、同じ大きさでは足りない。

- 主役（§1の表）の立ち絵を、その人の席側に**大きく**置く
- **絶対に手牌にも役にもかぶせないこと。**いまの問題の裏返しになる
- 振り込みのときの主役は**和了った相手**。自分ではない。
  自分の立ち絵は出さないか、小さく沈めて出す

### 縦持ち

箱の中央寄せを直す。縦では卓の下に帯が入るので、
**卓を上へ寄せ、帯を下端に固定する。**中途半端な位置に浮かせない。

---

## 4. 勝ちと負けで画面を変える

色を変えるだけでは足りない。**動きの向きを変える。**

### 自分が和了ったとき

- 帯は**下から立ち上がる**
- 集中線を回す（段4のコールバナーの仕組みが使える）
- 数字は金。カウントアップさせる
- 立ち絵は少し跳ねて入る

### 自分が振り込んだとき

- 帯は**上から降りて、沈む**
- 集中線を出さない
- 数字は赤。**カウントダウンさせる**
- 自分の席プレートを暗く落とす
- **画面全体をわずかに冷たくする**（彩度を少し落とす程度。やりすぎない）

### 他家同士

- どちらでもない。素早く、静かに出して、静かに消える

**負けの演出を派手にしないこと。**振り込みは一局に何度も起きる。
そのたびに大げさな演出が入ると、遊ぶのが嫌になる。
**沈むことは伝えるが、痛めつけないこと。**

---

## 5. 点棒を飛ばす

段3のkeyed＋FLIPがそのまま使える。

- **払う人の席プレートから、和了った人の席プレートへ棒を飛ばす**
- 飛んでいる間に、両方のプレートの数字が動く。
  着地した瞬間に最終値になること
- ツモは**3本が同時に**飛ぶ。子と親で本数ではなく太さか色を変える
- 供託のリーチ棒は中央から和了った人へ。既に中央に出ているものが動く
- 本場の積み棒も同様

**ここが「誰が誰にいくら払ったか」を見せる唯一の場所になる。**
数字が黙って書き換わるのをやめる。

### 速度

- `UI.speed` に従う。最速では飛ばさず、即座に確定させる
- `prefers-reduced-motion` でも飛ばさない
- **タップで飛ばせること。**演出を最後まで見たくない人が必ずいる

## 6. 流局

**表をやめる。**支払い後の点数を並べても、何が起きたか分からない。

- 各席のプレートに**テンパイ／ノーテン**の印を出す
- 聴牌料を§5と同じ仕組みで飛ばす
- 流局の種類（荒牌平局・途中流局）は中央に短く出す
- 親の連荘かどうかを明示する。**これが次の局に直接効く情報**

テンパイしていた人の手牌は卓の上で倒す。和了と同じ扱いにする。

## 7. 対局終了

**`ui.js` の `gameOver` ではなく `match.js:373` の `UI.modal` を作り直すこと。**
`ui.js:733` の実装は785行目で上書きされていて、誰も呼んでいない。

- **`ui.js:733` の死んでいる `gameOver` は削除する。**残すと次に読む人が必ず騙される。
  `_lastRank` を使っている側だけ残す
- 見出しが「単体の対局」になっているのは `opts.title` がそのまま出ているため。
  対局終了専用の見出しに変える

内容は順位表。四人の立ち絵・順位・最終点・素点の増減。
一位の演出だけ他と分ける。**ここは局ではなく半荘の締めなので、和了画面より重くてよい。**

## 10. 実装で決めたこと（作業の記録）

指示書に書かれていない粒度で、実装のときに決めたもの。**ここを外すと崩れる。**

### `game.js` に一行だけ足した（流局の `payments`）

§0 は「四分岐の判定に `game.js` へ足すものは無い」と書いてあり、そのとおりだった。
ただし**§5・§6 の点棒**には足りない。和了は `finishWin` が `payments`（誰がいくら払ったか）
を渡してくるが、**流局は渡してこない**（`tenpai` の真偽だけ）。

聴牌料の式（`3000/n` と `3000/(4-n)`）を `ui.js` 側で組み直すこともできるが、
**同じ規則を二か所に書くことになる**——このリポジトリが何度も踏んでいる罠
（`RULES.event`、交渉の `detail`）。`exhaustiveDraw` が既に計算している値を
そのまま `payments` に載せて渡す形にした。

**`game.js` が増えたのはこの一箇所だけ。**`Sound` は一行も入っていない
（`CLAUDE.md` の急所はそちら）。

### 点数は「もう払い終わった値」で届く

`finishWin` も `exhaustiveDraw` も、**`io.result` を呼ぶ前に `p.score` を書き換えている。**
だから `data` から届くのは**支払い後**の値で、飛ばす前の値は
`p.score − その席の増減` で戻す。ここを取り違えると、
「飛んでいる最中に正しい値、着地して元の値」という逆再生になる。

### 冷たくするのに `filter` を使わない

§4 の「画面全体をわずかに冷たくする」を `filter:saturate()` で書かない。
`#app` は `#felt`（`rotateX` ＋ `preserve-3d`）の祖先なので、
**牌の厚みが潰れる危険がある**（`spec.md` §5.1 の「`#center` から牌までに
`overflow:hidden` や `filter` を挟まない」と同じ話）。
青い膜を一枚重ねる（`.endTint`）。見た目は同じで、3D に触らない。

### 立ち絵の左右はカットインと同じ規則で決める

`(seat === 0 || seat === 3) ? 'left' : 'right'`。`say()` が既に使っている式で、
**同じ人がカットインと立ち絵で左右に飛ばない。**席の実座標から決めると、
四人卓と列レイアウトで規則が割れる。

### 帯は `#myarea` を覆う。卓には掛けない

帯（`#endband`）は `#app` の下端に絶対配置で、高さは `#myarea` のぶんだけ。
**卓（`#table`）には一切掛からない。**これが §3 の「卓を消さない」の実体。
立ち絵（`#endbust`）は左右の端で、**帯の上端で止める**（`bottom` を帯の高さに合わせる）
——手牌にも役にもかぶせないための錠。

### 倒した手牌は `render()` が描く。帯とは別物

`this._end.reveal`（席の集合）を `render()` の `oppHTML` が読む。
イカサマの `c.reveal` と同じ経路に相乗りしている。
**帯の中の牌と、卓の上で倒れている牌は別のノード**——前者は和了手の再掲、
後者は `_nodes` の keyed な牌。混ぜない。

### 送る速さ

- **四分岐すべてタップを待つ**（§1・2026年9月5日に直した）。
  自動で送るのは `this.auto`（おまかせ）と `speed === 0`（最速）のときだけ
  ——そこは人が見ていない。**`kind` で分けないこと**
  （`tools/test-match.js` が四つとも同じ扱いであることを固定している）
- 演出中のどこを押しても飛ばせる（§5）。押した瞬間に最終値へ確定する
- `speed === 0` と `prefers-reduced-motion` は最初から飛ばさない（`UI.animates`）
- **送ったあとの click を一回だけ飲む**（`UI.eatGhostClick`・2026年9月5日）。
  送りは `pointerdown` で受けるので、**指が離れる前に帯が畳まれる。**
  iOS Safari は「押した相手が消えていたら**離した場所にいる相手**」へ click を出すので、
  **帯の下にあったものがそのまま押される。**実測（844×334）で帯の下にいるのは
  **手牌（100%）**と、直す前は**「おまかせ」の釦（100%）**だった。
  （`HANDOVER.md` §5「締めの帯の下に、押せるものを置かない」）。
  **飲まないのは `#overlay` だけ**——最後の局を送った直後に対局終了の札が出るので、
  そこを飲むと一度目の指が効かなくなる

## 11. 追加分の記録（§A・§B・§C）

### 立ち絵は「名札」で言う。位置では言えない（§A-1）

ロンの主役は自分、放銃の主役は相手。**立ち絵は同じ場所に出る**ので、
顔だけでは誰のものか分からなかった。席プレートと同じ形の札（自風＋名前）を
立ち絵に載せ、自分なら同じ桃色にする。主役の席プレートには `.star`（立ち絵と同じ金の枠）。

**札は立ち絵の上に置くこと。**下に置くと席プレート（`z-index:5`）の裏に回って読めない
——立ち絵は卓より下の層にいるので、重なった側が必ず勝つ。

### 桃色は「自分の席」だけ（§A-2）

段4で決めた「自分の席だけ色を反転させる」が、リーチの桃色と衝突していた。
**桃色のプレートが二つ出る**（自分とリーチした他家）。リーチは白へ寄せた
——供託のリーチ棒（`.riichi-stick`）が白なので、意味が繋がる。
**これは和了画面だけの話ではない。**対局中の画面にも同じ衝突があった（段4からの持ち越し）。

### 他家同士は「和了った人の点」が主（§B-1）

`±0` を一番大きく出すと、**自分に何も起きていないことを画面で一番大きく主張する。**
`scoreLead` を立てて和了った人の合計点を大きくし、自分の増減は `±0` のとき消す。

### 副露は preserve-3d が切れていた（§C-1）

厚みの CSS（`.opp .melds .tile::before`）は最初から書いてあったが、
**`.melds` と `.meld` が `transform-style:flat`** だったので、
`rotateX(-90deg)` した面が親の平面に潰れ、**平らな板として貼り付いていた。**
`#left` と `#felt` は `preserve-3d` なので、間のこの二つだけが抜けていた。
`spec.md` §5.1 の「`#center` から牌までに `overflow:hidden` や `filter` を挟まない」と同じ罠で、
**切れる場所は祖先とはかぎらない。**

### 帯の下に、押せるものを置かない（2026年9月5日）

**帯そのものではなく、帯の下に何がいるか**の話。844×334 で測ると、
帯は画面の下 132px（y202〜334）を覆い、その下に

- `#topbar`（おまかせ／横画面にする）… 四人卓では右下に置いていたので **100% 重なる**
- `#handrow`（手牌）… **100% 重なる**（どのレイアウトでも）

がいた。回転表示（`body.four rotated`）では `#giveup` と `#rotateBtn` の両方。
縦の列レイアウトは `#topbar` が上にあるので、下にいるのは手牌だけ。

帯を叩いて送った指の click は、上の幽霊クリックで**その下にあるものへ落ちうる。**
「おまかせ」がそれを踏むと残りの局が早送りで消化され、
**打ち手には「一局で終わった」としか見えない。**

**注意。**この重なりは「実機で東1局から戻る」という報告を追っていて見つけたが、
**あの症状の原因ではなかった**（実体は iOS Chrome の再読み込み。`BACKLOG.md`）。
Safari で踏んだ証拠は無い。**踏める形になっていた**ので直した、というだけのこと。

直しは二重。**`#topbar` を右上へ**（卓面 y33〜と対面の札 x〜500 の外側で空いている）と、
**送ったあとの click を飲む。**片方だけにしないこと——上へ逃がしても
**手牌は帯の下に残る**（幽霊クリックが牌を切りうる）し、飲むだけでは
「見えない釦が下にいる」という形そのものが残る。

錠は `tools/test-match.js`（`match.css` に `bottom:` が無いこと）と
`tools/drive-match.js --play --width 844 --height 334`（局数と `giveUp` の回数）。

### 鳴いた牌の横倒しは「無かった」（§C-1）

指示書は「横向きに倒した牌だけ見える面が変わる」と書いてあるが、
**`meldHTML` に回転そのものが無かった**（ただ四枚並べていた）。実装した。

- 鳴いた牌は `m.tiles` の**末尾**（`used.concat([tileId])`）。加槓はそのあとに
  もう一枚 push されるので、**末尾から二番目**が鳴いた牌になる
- 倒す位置は麻雀の作法どおり **上家＝左端／対面＝真ん中／下家＝右端**（`m.from` と席から出す）
- **牌そのものを回す**ので、厚みの面は牌のローカル座標のまま付いてきて、
  見える面が自動的に側面へ変わる（`.rslot` の四方向と同じ理屈）
- 回した牌は見かけの幅と高さが入れ替わるが、**レイアウトの箱は回らない。**
  `.meldSide` を `--mh` 幅で取り直し、中で牌を絶対配置して下端にそろえる。
  加槓の四枚目はその上へ重ねる
- 暗槓は倒さない（両端が裏のまま）
