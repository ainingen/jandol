## 0. 何をするのか

いまの直営雀荘は「営業ボタン → 裏で計算 → 結果表がポップアップ」で、
店が見えない。これを **ガールズ雀荘のフロアを見せて、一日が流れるのを眺める**
形に作り替える。カイロソフト系の経営ゲームの手触りを目標にする。

作るものは大きく5つ。

1. フロアの俯瞰ビューと一日の再生（ドット絵）
2. 客タイプ24種と、段階的に名前が分かっていく常連システム
3. 客をタップして「これは誰か」を見る客カード
4. 代表が打てる4つの卓（ボトルを賭ける。金は賭けない）
5. ガールズ雀荘の内装と、設備を買い足して派手になっていく流れ

**この指示書はモックアップ画像とセットで読むこと。** 配色・レイアウト・
スプライトの形は画像が正。文章と食い違ったら画像を優先する。

添付画像:
- `girls-ivory.png` … フロア全景（完成イメージ）
- `floor-staff.png` … スタッフをフロアに配置した状態
- `staff-ab.png` … スタッフ表現のA案B案比較（**B案を採用**）
- `customer-types.png` … 客タイプ24種
- `customer-card.png` … 客カード（タップ時）
- `bottle-tiers.png` … ボトル6段階
- `bottle-dialog.png` … ボトル勝負ダイアログ
- `names.py` … 名前生成の参照実装（Pythonなのでjsに移植する）

## 1. 最重要の設計判断 —「先に全部計算、再生は演出のみ」

**乱数を使う処理はすべて再生開始前に確定させる。**

1. `runDay()` の頭で、いまと同じように `computeDay()` を回し、
   `pickEvent()` でイベントを引き、成長の着順ロールまで**全部先に決める**
2. その確定結果から「タイムライン」（時刻付きの演出イベント列）を生成する
3. 再生層はタイムラインを順に消化するだけ。**乱数を一切引かない**

こうする理由:
- **スキップしても倍速でも結果が完全に同一**になる（スキップ＝即時消化）
- 演出をいくら作り替えても数値バランスが壊れない
- テストは「タイムライン生成」の純関数だけ見ればよい

**例外は実対局に入る分岐だけ**（荒らし／ボトル勝負／`joinNight` の同卓）。
プレイヤーの選択と実プレイ結果が要るので、タイムライン上に「割り込み点」を
置き、そこで再生を止めて従来の流れを実行し、結果を受けて続きを消化する。

## 2. 守ること（既存の決めごと。破らない）

- **canvas は表紙の一枚だけ**（PLiCyのサムネイル制約）。フロアに canvas は使わない
- 新規ファイルは `build.py` の `CSS` / `JS` リストに**追記しないと取り込まれない**
- セーブは他画面の項目を消さない（読んだものを全部残して書き戻す）
- **日本語識別子は使わない**
- **画面に出す新しい文言を足したら `python3 tools/make-font.py` を実行し直す。**
  今回は文言が大量に増える（客タイプ名24種、性格ラベル、ボトル名、セリフ、
  生成される人名の姓40＋名40＋二つ名10）。入っていない字はその一文字だけ
  別書体になる。**とくに人名の漢字は要注意**（検証中に「鴉」が未収録だと判明した）。
  名前生成に使う全文字を、フォント生成の入力に必ず含めること
- `index.html` は直接編集しない。`src/` を直して `python3 build.py`
- ブラウザ検証は必ず `python3 -m http.server 8765` 経由（`file://` は canvas が汚染される）

## 4. 絵の作り方（ドット絵）

### 4.1 描画方式

フロアは **低解像度で描いて整数倍に拡大**する。基準解像度 **200×164**、
表示倍率は幅に合わせて可変（モックは5倍）。

canvas が使えないので、実装手段は次の順で検討すること:

1. **SVG に `shape-rendering="crispEdges"` で矩形を並べる**（第一候補）
2. CSS の `box-shadow` によるピクセルアート
3. どうしても厳しければ、事前に PNG スプライトを生成して
   `image-rendering: pixelated` で拡大

いずれの場合も **拡大は必ず整数倍・ニアレストネイバー相当**にすること。
補間が入るとドット絵が台無しになる。

### 4.2 二層構造

カイロソフト系と同じく **ピクセル層＋くっきりUI層**の2層に分ける。

- **ピクセル層**: 床・壁・卓・客・スタッフの体・ネオン・設備
- **UI層**（等倍のDOM/テキスト）: 上部バー、金額ポップ、満卓札、
  ティッカー、客カード、ダイアログ、スタッフの丸写真と名前札

ドットの世界に日本語テキストを直接置くと潰れて読めない。文字は必ずUI層。

### 4.3 パレット（ガールズ雀荘）

```
床（カーペット）  #d4c6b2 / #ccbda8   柄 #baa692 / #c4b29e   縁 #a88e78
壁               #301634   壁の下端 #241028
ネオン ピンク     #ff56b2    シアン #60e8ff   黄 #ffe86e   緑 #96ffb4
卓の縁           #a668ce   自分の卓 #60a0e1   呼ばれた卓 #ffce50
ラシャ（ピンク）  #ce3a84   上端 #f06eb0   下端 #a02064
牌               #fffcf0 / #cec6b2
UIパネル         #542c4c   文字 #fff6e0   補助 #eebee1
金               #ffce50   ハイライト #ffe86e
アウトライン     #3e2c24（全スプライト共通）
```

**カーペットはアイボリーだが明度は抑える**（`#d4c6b2` 前後）。
明るすぎると目が痛く、ドットのきらめきも飛ぶ。検証で確認済み。

床が明るいので、卓の照明は「明るくする」のではなく
**わずかにピンクを差す**処理にする（加算すると白飛びする）。

### 4.4 客スプライト

**12×16ドット、3頭身。** 顔が6px幅とれるので表情が出る。

構成: 濃茶のアウトライン → 顔 → 髪（前髪1段＋側面） → 目（2px、白ハイライト）
→ ほお紅 → 体（制服/私服） → 手 → 足。
足の位置を左右入れ替えるだけで歩行2フレームになる。

タイプの描き分けは **シルエット（帽子・髪型）＋色＋持ち物** の3点セット。
色だけで分けると小さくて判別できない。詳細は `customer-types.png` を見ること。

床が明るいので、**全スプライトの足元に楕円の影**（`#b29e8c`）を敷く。

### 4.5 スタッフ（雀ドル）の見せ方 — B案を採用

**丸写真の頭（実写・金縁）＋ドットの体（ピンクの制服・金の襟と帯）。**

丸写真だけだと床に浮いて、客と同じ世界に立っていないように見える
（`staff-ab.png` の左が却下したA案）。体を付けると歩けるし、
客と並んでも違和感がない。頭が大きいのはカイロ的な誇張として機能する。

- 頭: `img/{id3}.webp` を円形クリップ、直径50px相当、金縁4px
- 体: 7px単位で 8×7 ドット。ピンクの制服 `#e84896`、金の襟と帯、両脇に手
- 名前札: 体の下にUI層で。**実キャラ名を使う**（`characters.js` の `name`）
- 指名が入っている子は頭の右上にハート（♥はフォント未収録なので図形で描く）
- 状態は3つ: 卓のそばで接客中／通路を歩行中（足入れ替え＋足元に土埃）／同卓中

壁の出勤パネルは**残す**。フロアの丸写真は「今どこで何をしているか」、
壁パネルは「今日の出勤メンバー」で役割が違う。

### 4.6 フォント

**すべての文字を丸ゴシック（`fonts/maru-ui.woff2`）で出す。** ゴシックだと
事務的で、ガールズ雀荘の空気にもドットのポップさにも合わない。

この書体は1ウェイトしかない。太字が要るところは縁取り（stroke）で太らせるが、
**小さい字を太らせると潰れる**ので 18px 相当以上に限ること。

`♥` `★` `×` はフォント未収録。**図形で描く**（ハート＝円2つ＋三角、
星＝10点ポリゴン、バツ＝線2本）。

## 5. 一日の再生

### 5.1 時間の設計（1倍速）

昼14秒 / 夕14秒 / 夜18秒、幕間1秒 → 一日およそ48秒。
倍速 ×1 / ×2 / ×4、スキップあり。速度は `parlor.speed` に保存（既定1）。

### 5.2 タイムラインのイベント種別

| 種別 | 内容 |
|---|---|
| `slotStart {key}` | 時間帯の見出し、照明の切り替え |
| `arrive {slot, typeKey, guestId, seatHint}` | 客が入口から歩いて空席に着く |
| `pay {amount, tableIdx}` | 卓の上に「+2,600円」がポップ、売上カウンタ加算 |
| `leave {guestId}` | 客が席を立って出ていく |
| `full {slot}` | 満卓の札（`day.slots[i].full` のとき） |
| `staffMove {charaId, to}` | スタッフが卓のあいだを歩く |
| `nominate {charaId}` | 指名が入る。頭上にハート、ティッカーに流す |
| `bottle {tier, charaId}` | ボトルが入る。売上加算＋ボトル棚の演出 |
| `interrupt {node}` | 割り込み点（実対局・選択肢） |
| `dayEnd` | 閉店 |

### 5.3 数値の展開ルール

- 各時間帯の `guests` 人ぶんの `arrive` を、帯の時間内に
  **前半やや疎・後半やや密**で散らす
- `pay` は一人一回、`fee` を基本にしつつ、
  **帯の合計が `day.slots[i].sales` に厳密に一致するよう最後の一人で端数調整**
- 席の管理は見た目の整合だけでよい。空きが無ければ入口で待たせ、
  `leave` の後に着席させる。延べ人数の厳密な収支は追わない
- `shugi` / `oshinobi` の臨時収入は該当帯の途中に演出として混ぜる
- **`joinNight` が有効なとき、夜の売上は `computeDay` が既に自分の卓のぶんを
  引いている。再生側で二重に減らさないこと**

## 6. 客タイプ24種

`customer-types.png` が仕様。4カテゴリ。

**一般客**（店の土台）: 学生 / 会社帰り / 隠居 / カップル / ママ友 / サークル / 教室の生徒
**上客**（機嫌よく帰すと大きい）: マダム / 観光客 / 推しファン / 社長
**厄介**（放っておくと損）: 酔っ払い / 荒らし / 引き抜き屋 / 勧誘マン / 雀荘ジプシー / 他店の主
**特別**（ゲームが動く）: 打ち師 / 常連の主 / 記者 / 師匠 / 配信者 / 元雀ドル / 協会の人

各タイプが持つデータ:

```js
{ key, name, hair, hairDark, cloth, clothDark, deco,   // 見た目
  slots: [0,1,2],        // 出やすい時間帯
  feeMul: 1.0,           // 場代の倍率（演出上の内訳。合計は sales に合わせる）
  weight: 10,            // 出現の重み
  personality: 'ねばる', // 性格ラベル
  effect: {...} }        // ゲーム上の効果
```

### 6.1 とくに重要な3タイプ

**推しファン** — 推しの雀ドルが出勤している日だけ来る。好感度（`favor`）が
上がるほど人数が増える。**これがあると「誰を出勤させるか」が売上に直結し、
育成と経営が噛み合う。** 現状は出勤者が係数を上げるだけなので、ここを繋ぐ。

**引き抜き屋** — 他事務所のスカウト。放置すると雀ドルの `favor` が下がる。
雀荘が「金を稼ぐ場所」から「事務所の防衛の場」になる。

**師匠** — 同卓した雀ドルの `addExp` が大きく進む。雀荘が育成施設になる。

### 6.2 効果の実装方針

第一段では**演出と客カードの表示まで**を作り、効果は次の3つだけ実装する:
推しファン（人数が `favor` に連動）、荒らし（既存イベントと接続）、
常連の主（後述の昇格の到達点）。
残りは `effect` を定義だけしておき、第二段で有効化する。
**一度に全部繋ぐとバランスが崩れて原因の切り分けができなくなる。**

## 7. 名前と常連システム

`names.py` が参照実装。jsに移植する。

**4段階で少しずつ名前が分かっていく。**

| 段階 | 条件 | 表示 | 例 |
|---|---|---|---|
| 0 一見さん | 初回 | タイプ由来の通称 | 「スーツの人」「うちわを持った人」 |
| 1 顔なじみ | 3回 | 名字だけ | 「後藤さん」 |
| 2 常連 | 10回 | フルネーム | 「近藤大輔」 |
| 3 主 | 30回 | 二つ名つき | 「リーチ一直線の渡辺勝」 |

最初から全員に名前を振ると誰も覚えられない。通うほど名前が分かると
**常連化そのものがご褒美**になる。客カードに「あと3回で常連
（フルネームが分かる）」の進捗バーを出す。

データ: 姓40 / 男名20 / 女名20 / 二つ名10 / タイプ別の通称24。
タイプによって性別の傾向を持たせる（マダム・ママ友・元雀ドルは女性、
隠居・社長・荒らし・引き抜き屋・協会の人・師匠・他店の主・酔っ払いは男性、
それ以外は両方）。

保存: `parlor.regulars = { [guestId]: {typeKey, visits, sei, mei, nijina, favTalent} }`。
**一見さんは保存しない**（毎日大量に増えてセーブが膨らむ）。
3回目に到達した時点で初めて `regulars` に登録する。
上限200人、超えたら訪問回数の少ない順に落とす。

段階0のときの `guestId` はその日限りの一時IDでよい。

## 8. 客カード（タップ）

`customer-card.png` が仕様。

客スプライトをタップすると再生が一時停止し、カードが開く。

表示: タイプ名（カテゴリ色の帯）／性格ラベル／大きいスプライト／
表示名／段階の説明（「まだ名字しか知らない」）／来店回数と次段階までの
進捗バー／お目当ての雀ドル／今夜のお勘定／この店の好み／ひとことセリフ。

ボタンは「この客を覚える」（`regulars` に強制登録＝段階1へ）と「とじる」。

タップ判定はUI層に透明な当たり判定を置く。ドットの拡大倍率が変わっても
座標がずれないよう、**フロア座標→画面座標の変換を一箇所にまとめる**こと。

## 9. 代表が打てる4つの卓 — ボトル勝負

**金は賭けない。負けたほうが「ボトルを入れる」。**
代表が勝てば客がボトルを入れて売上になり、負ければ店が一本おごって在庫が減る。

`bottle-tiers.png` / `bottle-dialog.png` が仕様。

### 9.1 4つの卓

| 呼ばれ方 | 客 | 賭かるもの | 勝てば／負ければ | 断ると |
|---|---|---|---|---|
| いつもの人と一局 | 常連の主 | ビール | 忠誠が上がる／失うものなし | 何も起きない |
| 名指しの果たし状 | 代表指名客 | ハウスボトル〜日本酒 | 評判が大きく伸びる／評判が下がる | 評判が少し下がる |
| 黙らせる一局 | 荒らし・酔っ払い | 相手の言い値 | その場で追い出せる／客が帰り売上が飛ぶ | 用心棒・警察など別解あり |
| ボトルを賭ける | デカピン客・社長 | ワイン〜タワー | 客が入れる（大きい）／店がおごる（在庫−1） | 何も起きない |

**危険度の階段になっている。** 序盤は常連と気軽に打ち、評判が上がると
指名客が来て、店に余裕が出てから高い酒に手を出す。
最上位は完全任意なので、堅実にやりたいプレイヤーは一生無視できる。

### 9.2 ボトル6段階

| # | 名前 | 売上 |
|---|---|---|
| 1 | ビール | 12,000円 |
| 2 | ハウスボトル | 30,000円 |
| 3 | 日本酒 | 60,000円 |
| 4 | ワイン | 120,000円 |
| 5 | シャンパン（ドンペリ） | 300,000円 |
| 6 | シャンパンタワー | 800,000円 |

**常連の格が上がるほど賭かるボトルの格も上がる**（段階0-1はビール止まり、
段階3の主はワイン以上）。常連育成がそのまま勝負の格上げになる。
タワーは年に数回の大一番のみ。翌日以降の来客が増える `buffs` を積む。

### 9.3 歯止め（必ず入れる）

- **代表が打てるのは1日1回まで。** 実対局は1回で数分かかる。無制限だと
  「営業を眺める」テンポが完全に壊れる。ダイアログに残り回数を明記する
- **迷惑客には打たない解決策を残す**（用心棒を雇う・警察を呼ぶ）。
  麻雀が苦手なプレイヤーが詰まないように
- 断っても評判が下がるのは「名指しの果たし状」だけ

### 9.4 実装

既存の `playOrSimulate(table, title)` にそのまま繋ぐ。
荒らし戦は既存の `ev.kind === 'arashi'` の処理をボトル賭けに置き換える
（`ARASHI_STAKE` の金銭授受をボトル在庫と売上に差し替え）。
勝敗判定は既存と同じく `rank.find(r => r.chara.id === 0)` の着順比較。

在庫: `parlor.bottles = [0,0,0,0,0,0]`（段階別の本数）。
`normalize()` に既定値を追加。おごるとき在庫が無ければ仕入れ費を引く。

## 10. 内装と設備

内装は**買い足すほど派手になっていく**ようにする。開店時は素っ気ない部屋で、
カーペット → ネオン → ミラーボール → 出勤パネル → スタンド花 → ソファ席 →
ドリンクカウンター、と揃って完成イメージ（`girls-ivory.png`）になる。
そのほうが投資の手応えが出る。

既存の `INTERIOR`（5段階）の各レベルに、フロアに描く設備を対応づける。
既存の数値（`mul`）は変えない。名前だけガールズ雀荘に合うよう改める。

`AUTO`（全自動卓）は卓の見た目、`SIGN`（看板）は店頭のネオンに反映する。

## 11. セーブ

`parlor` に追加するもの:

```js
speed: 1,                 // 再生速度
bottles: [0,0,0,0,0,0],   // ボトル在庫
regulars: {},             // 常連（段階1以上のみ）
challengedToday: false,   // 今日もう打ったか
```

`normalize()` に既定値を追加する。既存セーブを読んでも壊れないこと。
タイムラインと再生状態は保存しない（営業中にリロードされたらその日は
無かったことになる。金の移動は締めまで `store.set` しないので破綻しない）。

## 13. テストと検証

**node の純関数テスト**（`JansouFloor.build` / `JansouGuests`）:
- 各帯の `pay` 合計が `day.slots[i].sales` に**厳密一致**
- `arrive` の件数が `guests` に一致
- タイムラインが時刻昇順
- **rng を固定して、スキップ消化と通常消化で `store` に入る結果が完全一致**
- 名前生成: 段階0〜3で正しい形式、`regulars` の上限200で溢れが落ちる

**ブラウザ検証**（必ず `http://localhost:8765` 経由、Puppeteer `--no-sandbox`）:
- 卓2／卓8 の両方でフロアが崩れない
- 縦持ち幅（〜380px）と横持ち
- 客タップ → カード → とじる → 再生再開
- ボトル勝負 → 受けて立つ → 実対局 → 復帰
- `joinNight` オンで夜の割り込み
- **拡大がニアレストネイバーになっているか**（スクショを拡大して境界を目視）
- 既存セーブ（`parlor` に新項目が無いもの）を読み込んで壊れない

**既存の35件のユニットテストを実行して通ること**（エンジンには触らないので
通るはずだが確認する）。

## 14. 進め方

一度に全部作らない。この順で、各段階で動く状態にしてからコミットする。

1. **フロアが描けるところまで**（静止画。客・スタッフ・設備を配置するだけ）
2. **一日の再生**（タイムライン生成＋再生＋スキップ・倍速）。ここで
   スキップと通常再生の結果一致をテストする
3. **客タイプと名前・常連**（客カードまで）
4. **ボトル勝負**（4つの卓）
5. **内装の段階反映**

各段階の終わりに `python3 build.py` を通し、`tools/make-font.py` を
実行し直すこと。
