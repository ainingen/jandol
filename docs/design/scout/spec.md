## 0. なぜここを厚くするのか

遠征という**器**（日数・費用・同行者・留守番）は第三段でできた。
だが中身は `drawOne` の抽選一回で「見つかった／いませんでした」の二値のまま。
**プレイヤーが介在する余地が無い。**

コンセプトの先頭は「全国の雀荘を歩いて雀ドルを**見つけ**、**口説き**」であり、
副題は「その雀荘に、まだ見ぬ雀ドルがいる」。
**ゲームの看板がいちばん薄い。**

第五段（疲労・調子）は配分の判断を面白くする仕組みだが、
**配分先であるスカウトが薄いままだと判断が痩せる。**
また第五段は再測を伴うので、スカウトの日数の使われ方が変わる前に測ると
測り直しになる。だから第五段の前に割り込ませる。

## 1. 触らないもの

- **`Jansou.computeDay()` と `parlor` の経済。**遠征先の店は帳簿を持たない
- **`JansouFloor.build`（タイムライン生成）。**遠征先の店は
  タイムラインを持たない。**一日を再生しない**
- **`Scout.evaluate()` と `RULES` の判定そのもの。**
  変えるのは判定の**前後に何を見せるか**だけ
- **既存のパレット**（`jansou/spec.md` §4.3）。差し替えるのは
  店の型ごとの**壁・床・卓の三色だけ**。任意の色は振らない

## 2. 報告：`JansouFloor` を遠征先の店に使えるか

**使える。** 読んで確かめた結果を先に書く。

### 2.1 静止画として描く口はすでにある

`JansouFloor.mount(host).render(state)` が**一枚を描いて止まる**。
`state` は `{ parlor, staff, guests, closedTables, myTable, headNote, slot, sales, ticker }`。
`jansou.js` の `previewState()`（開店前の「夜のようす」）がすでにこの形で
**タイムライン無しの一枚**を出している。遠征先の店も同じ形でよい。

`buildRoom()` は `reconcile(parlor.floor, {tables, interior})` を通すので、
**`floor` を持たない擬似 `parlor` を渡せば `autoPlace` が卓を組む。**
指示どおり「卓の配置は `autoPlace` で組めばよい」がそのまま通る。

### 2.2 色は `<symbol>` に焼き込まれていない（部屋については）

| 描くもの | 描きかた | 差し替え |
|---|---|---|
| 壁・ネオン | `drawWall(g, parlor)` が `rect(..., PAL.wall)` | **差し替えられる** |
| 床（カーペット／板張り） | `drawCarpet(g, parlor)` が `rect(..., PAL.carpetA)` 他 | **差し替えられる** |
| 卓・ラシャ | `drawTable(g, t, kind, auto)` が `rect(..., PAL.felt)` 他 | **差し替えられる** |
| 設備（ソファ・カウンター等） | `drawFixtures(g, floor, parlor)` が `PAL.panel` 他 | 差し替えられる |
| **客のスプライト** | `guestDef()` が `<g id="jnc-...">` を作り、`JansouGuests` の型ごとの色を**焼いて** `defs` に置く | 焼き込み。**触らない** |
| **スタッフの体** | `buildRoom()` が `<g id="jns-body">` を `PAL.staffCloth`/`staffTrim` で**焼いて** `defs` に置く | 焼き込み。**触らない** |

つまり **部屋（壁・床・卓）は毎回 `rect()` で描き直しているので自由に差し替えられ、
人（客とスタッフ）だけが `<symbol>` に焼き込まれている。**
差し替えたいのは部屋の三色だけなので、**焼き込みは邪魔にならない。**

**やる変更は一つ。**`drawWall` / `drawCarpet` / `drawTable` / `drawFixtures` に
第三（第四）引数 `pal` を足し、既定を `PAL` にする。`buildRoom()` は
`opts.pal ? Object.assign({}, PAL, opts.pal) : PAL` を渡す。
**浅いマージにすること。**ネオンや金の色まで差し替えると型の色が壊れる。

`PAL` は `JansouFloor.PAL` として既に公開されているので、
店の型の側から派生色を書ける。

### 2.3 足りないもの三つ（新しく作る）

1. **止まったまま動き続ける口が無い。**`render()` は一枚描いて終わり、
   アニメを回すのは `play(timeline, hooks)` だけ。
   打牌の手・ネオン・ミラーボールは `drawActors()` が
   **`live.clock` だけから**位相を出しているので（乱数を引いていない）、
   **時計を進めるだけの `idle()` を足せばそのまま動く。**

   ```js
   // JansouFloor.mount(...).idle(hooks) — タイムラインを消化しない再生
   //   live.playing = true にして rAF で live.clock を進め、paint() するだけ
   //   停めるのは stop()。**タイムラインも割り込みも持たない**
   ```

   **`live.playing = true` にすること。**客のタップ判定
   （`jansou-floor.js` の `[data-guest]` ハンドラ）が
   `!live.playing` で弾いているので、立てないと声をかけられない。

2. **上のバーが自分の店の作り。**`mount()` が
   「ガールズ雀荘 〜雀ドル亭〜」と速度・スキップの釦を
   **無条件で**組んでいる。遠征先には要らない。
   `mount(host, { title, bare: true })` を足して、
   `bare` なら `.jnFlBar` を作らず、`title` を `.jnFlName` に入れる。

3. **癖の見た目。**下の §5。

## 3. 遠征先の店を見る

### 3.1 一日を再生しない（決定）

遠征先の店は**静止した一枚**として出す。理由は三つ。

- **自分の店との対比を保つ。**よその店は覗くだけ。
  一日が流れるのは自分の店だけ、という区別が経営の手応えを守る
- **遠征が長くなるのを避ける。**5日で4分は長い
- **探す行為に合わない。**動く客を追うのは反射神経の話になる。
  探すのは目で見て考える行為

ただし**乱数を使わない常時アニメはそのまま残す**——
打牌の手・ネオン・ミラーボール。完全に止まっていると死んで見える。
これらは `live.clock` だけから位相を出しているので、
§2.3 の `idle()` で時計を進めれば動く。**乱数は一切引かない。**

### 3.2 店の型は四つ

型は本拠地ではなく**行き先の県の `scale`** から重み付きで引く。
大きい県ほど高級店が出やすく、小さい県は古い店。

| key | 名前 | scale 1 | 2 | 3 | 4 | 5 |
|---|---|---|---|---|---|---|
| `old` | 古い雀荘 | 5 | 4 | 3 | 2 | 1 |
| `back` | 場末の店 | 4 | 4 | 3 | 2 | 1 |
| `girls` | 街のガールズ雀荘 | 1 | 2 | 3 | 4 | 4 |
| `lux` | 高級店 | 0 | 1 | 2 | 3 | 5 |

`scale 1` の県では高級店が出ない。`scale 5` では四つとも出るが高級店が最多。
**重みは初期値。**手応えを見てから動かす。

型は卓の数と内装の段にも効く（`autoPlace` の入力）:

| key | tables | interior | auto | sign |
|---|---|---|---|---|
| `old` | 2〜3 | 1 | 1 | 1 |
| `back` | 2〜4 | 1 | 1 | 1 |
| `girls` | 3〜5 | 3 | 2 | 2 |
| `lux` | 4〜6 | 5 | 3 | 3 |

**卓は6まで。**8卓は自分の店の終盤の絵で、よその店に出すと格が壊れる。

### 3.3 壁・床・卓の三色（既存パレットからの派生）

**実装で四つめが要った（A4.5-1）。**壁と卓だけ差し替えても、
**どの型の店も一目では同じに見えた。**理由は二つ。

1. `drawLight()` が夜の帯に**ピンクの覆い**を掛ける（`#301634` と `#ff56b2` の直書き）
2. 看板 lv1 のとき `drawWall()` が**消えたネオンで「GIRLS」**を描く。
   古い雀荘が自分の店の看板を掲げていては、型を差し替えた意味がなくなる

どちらも**部屋のもの**なので、型と一緒に決まるほうが素直。
`PAL` に `night` / `lamp` / `signOff` / `signOffLow` を出し、
**既定は直書きしてあった値そのまま**にした——だから
**自分の店の絵は1ドットも変わらない**（`tools/test-scout.js` で錠を掛けてある）。

| key | 夜の灯り `night` / `lamp` | 消えたネオン |
|---|---|---|
| `old` | `#3a3026` / `#ffb478`（裸電球） | 壁と同色＝見えない |
| `back` | `#24262e` / `#a8c0d0`（蛍光灯） | 壁と同色＝見えない |
| `girls` | **PAL のまま**（`#301634` / `#ff56b2`） | PAL のまま |
| `lux` | `#14211c` / `#d9b45e`（傘ランプの金） | 壁と同色＝見えない |

**枠は CSS で。**`.jnFloor` の既定はピンクの枠と紫の帯（自分の店の顔）なので、
`office.css` が `.jnFloor.bare` のときだけ事務所の金に差し替える。
`bare` は遠征先にしか付かないので、自分の店には効かない。

高級店の `sign` は **1**。2以上にすると `drawWall` が「GIRLS」のネオンを灯す。

**新しい色を発明しない。**すべて `jansou-floor.js` の `PAL`、
`src/theme.css`、`src/style.css` に既にある色か、その明度違い。

| key | 壁 `wall` / `wallLow` | 床 | 卓 `tableEdge` / `felt` | 由来 |
|---|---|---|---|---|
| `old` | `#3a3026` / `#2a2118` | 板張り `plankA:#a89478` | `#8a6a48` / `#2f6a4a` | 煙草で焼けた壁。緑ラシャは `style.css` の `--bamboo:#2e7d5b` から |
| `back` | `#24262e` / `#191b21` | `#8e8a80`（すり減ったリノリウム） | `#6a5a48` / `#4a5560` | 色褪せた青ラシャ。`--indigo:#2a5b93` を沈めたもの |
| `girls` | `#301634` / `#241028`（**PAL そのまま**） | `carpetA:#d4c6b2`（そのまま） | `#a668ce` / `#ce3a84`（そのまま） | 自分の店と同じ系統。差し替え無し |
| `lux` | `#14211c` / `#0e1a17` | `#b8a07a`（寄木） | `#2a1e14` / `#1f5646` | `theme.css` の `--urushi:#13201c` / `--urushi-3`、`style.css` の `--back:#1f5646`（牌の背の深緑） |

**差し替えるのはこの三系統だけ。**ネオン・金・客・スタッフの色は共通のまま。
`girls` が差し替え無しなのは意図的で、**自分の店と同じ絵が出ることで
「よそもうちと同じ商売をしている」**が伝わる。

### 3.4 誰がいるか

床には**客**と**スタッフ**がいて、その中に雀ドルが混じっている。

| 立ち位置 | 誰か | 声をかけると |
|---|---|---|
| 卓の席 | ほとんどはただの客。一部が**未契約の雀ドル**（素人として打っている） | 発見（`discovered` に入る） |
| 通路に立っている（スタッフ） | **他事務所の所属**か、この店の従業員 | 移籍の話＝引き抜き |
| 卓の席（既発見） | すでに `discovered` の子 | 口説く（§6） |

**未発見の子は名鑑と同じくシルエット。**声をかけて初めて誰か分かる。
シルエットは `--sil` / `--sil-img`（`meikan.css`）で既にある仕組みを使う。

**引き抜き（スタッフとして立っている子）は、この段では「発見」まで。**
移籍そのものの振る舞い（ライバル事務所の実体）は `ROADMAP.md` [F] のまま。

### 3.5 雀ドルが一人もいない日を許す（決定）

**毎日必ず誰かいる形にしない。**滞在日ごとに引き直すなら（§6.2）、
**空振りの日があること**が形の一部になる。

- 毎日誰かいると、**一日3回の上限が常に足りて緊張が消える。**
  「今日は当たりが濃い／薄い」の差が出ないと、3回の使いどころが生まれない
- **規模の小さい県ほど空振りが多い。**これが `scale` の意味の一つになり、
  県の一行紹介「まだ誰にも見つかっていない」とも噛み合う
  ——居ないことが多いから、居たときに価値がある

`drawOne` の重みで自然にそうなるとしても、**設計として明記する。**
実装は「その日一人でもいる確率」を `scale` から引き、
外れたら**その日は誰もいない**（`seats` はただの客だけになる）。

| `scale` | 1 | 2 | 3 | 4 | 5 |
|---|---|---|---|---|---|
| その日一人でもいる確率 | 0.35 | 0.45 | 0.55 | 0.62 | 0.70 |
| 二人目もいる確率（一人いたとき） | 0.10 | 0.15 | 0.22 | 0.30 | 0.38 |

**初期値。**手応えを見てから動かす。`scale 1` の県では
**三日に二日は空振り**になる。それでよい。

### 3.6 声をかけなかった子は、翌日の母集団から消えない（決定）

その日いた子に声をかけなければ、**翌日その店にはもういない。**
だが**母集団からは消えない**——別の日に、また会える。

`buildShop` が引くのは毎回 `Scout.findCandidates`（未発見者）の全体からで、
**「昨日いた子」を除外しない。**同じ子に二日続けて会うこともある。

**損失は時間で払う**、という方針（`office/spec.md` §1.3
「取り返しのつかない損失を置かない」）に沿う。
見送った子が永久に失われると、3回の上限が「間違えたら終わり」になり、
**上達の余地ではなく罰**になる。もう一度来ればまた会える。

## 4. 観察が無料、声をかけるのが有限（いちばん大事なところ）

### 4.1 そのままだと宝くじになる

20人いて3回押せて、当たりの場所が分からなければ、
**`drawOne` を絵で遠回しにしただけ**で、すぐ見抜かれる。
探す行為が成立するには、**声をかける前に情報が要る。**

材料は `characters.js` の `style`（打ち筋20種）。
雀荘なら打っているところを見れば打ち筋が分かる。
**スカウトが店でやることは本来それ。**

### 4.2 決めごと

- **観察は無料。**何度でも見てよい。時間も日数も減らない
- **声をかけるのは一日3回まで**（初期値 `CALLS_PER_DAY = 3`）。
  滞在が長いほど機会が増える＝**遠くまで行く理由**になる
- **癖は時刻だけから決まる形で描く。**`live.clock` の関数。
  **乱数を混ぜない**（`jansou/spec.md` §1 と同じ作法）。
  ただし**動きに頼らない**——離れていると振りかたは読めない（§4.5）。
  動くのは飾りで、判別を担うのは形と色
- **誰がどこにいるかは朝に確定させる**（§7）

### 4.3 「癖がある＝雀ドル」にしないこと（設計上の急所）

素直に「雀ドルにだけ癖を付ける」と、**観察が完全情報になる。**
癖のある子を探して押すだけで、3回の上限も、見抜く余地も意味を失う。
**指示の「見抜けば一発、見抜けなければ外す」が成立しない。**

だから二段にする。

1. **癖は「腕のある打ち手」に付く。**雀ドルには必ず付くが、
   **ただの客の一部にも付く**（打てる常連はいる）。
   割合は初期値で **雀ドル 100% / ただの客 25%**
2. **癖の濃さに段階がある。**雀ドルは**頭の上の印と体まわりの物が両方**付く
   （たとえば「立直棒が立っている」＋「速度線」）が、
   ただの客は**どちらか一つ**。遠目に「二つ付いている子」を探すことになる

これで「怪しいのが5人、押せるのは3回」という判断が生まれる。
**上限3回の中で、見抜けば一発、見抜けなければ外す。**

### 4.4 母集団を絞る — 雀ドルは女性の見た目（2026年9月4日に直した）

**最初の形は運ゲーだった。**実機で遊ぶと、店に20人ばらばらに座っている中から
誰を押すかの手がかりが無い。**男か女かすら分からなかった。**

`sex` は客タイプ24種すべてが持っているが、**名前の生成にしか使われておらず、
絵は男女を出し分けていなかった**（髪型は `style` から来ていて、
タイプごとに決まっている）。

だから二つ直す。

- **絵で男女が分かるようにする。**`grid(typeKey, frame, sex)` に `sex` を足し、
  女なら長い髪（`bob` / `long` / `bun` / `pony`）、男なら短い髪
  （`short` / `parted` / `bald` / `spiky`）に差し替える。
  **`sex` を渡さなければいままでどおり**——自分の店の絵は1ドットも変わらない
- **雀ドルは必ず女性の見た目**にする。ただの客は**大半が男**（`FEMALE_RATE`）。
  16席の店なら女性は3〜5人になり、**そこだけ見ればいい**。
  **上限3回が初めて生きる**——20人から3人選ぶのは運だが、4人から3人なら判断になる

タイプ自身の `sex` が `male` / `female` で決まっているものはそれに従い、
`both` のものだけを `FEMALE_RATE` で振る。

### 4.5 癖の語彙（離れていても分かる大きさで）

**最初の形は「12×16 の中に 1〜3ドットの印」だった。これが失敗だった。**
並べて見比べれば違いは分かるが、**店の中に20人ばらばらに座っている状態では
見つけられない。**「3倍で並べても混ざらない」という確認は、
**探す状況を再現できていなかった**（並べた比較でしか見ていなかった）。

**判別できない癖は、無いのと同じ。**

だから **スプライトの箱の外へ出す**。頭の上に浮かべるか、体の横・足元に
**輪郭からはみ出す大きさ**で置く。離れて見たときに効くのは
**シルエットが崩れているかどうか**で、箱の中の1ドットではない。

癖は6種のまま。**系統も二つのまま**（`beat` と `mark`）だが、
`beat` は「振りかた」ではなく**頭の上の印**になった
——振りかたは離れていると読めないため。

| 癖 | 系統 | 見た目 | 位置 | 意味 |
|---|---|---|---|---|
| `fast` 手が速い | beat | **速度線2本**（横向き）＋手が上がりっぱなし | 頭の上 | 速い・軽い |
| `slow` 長考する | beat | **縦に三点**（…） | 頭の上 | 重い・読む |
| `still` 動かない | beat | **横一本の長い帯**（凪） | 頭の上 | 冷たい・変則 |
| `bou` 立直棒 | mark | **縦に立った白い棒**（上端が赤） | 席の右 | 攻める |
| `meld` 鳴きが多い | mark | **晒し牌の塊**（横に張り出す） | 体の右下 | 仕掛ける |
| `guard` 河が横に長い | mark | **横に長い牌の列** | 足元 | 守る |

**色でも分ける。**頭の上の三つは形が似やすいので、
`fast` はシアン、`slow` は黄、`still` は**ピンク**。
3倍表示では色のほうが早く効く。

**灰は使えない。**最初は `still` を灰にしていたが、**場末の店の床が灰色**なので
そこで丸ごと消えた（下の「四型で確かめる」）。シアン・黄と色相がいちばん
離れていて、どの床の色とも当たらないのがピンクだった。

**印はすべて暗い縁で囲う**（`outlined`）。床は型ごとに変わるが、四つとも
中間の明るさ（板張り `#a89478` / リノリウム `#8e8a80` / カーペット `#d4c6b2` /
寄木 `#b8a07a`）なので、**明るい色を置くだけでは床に溶ける型が必ず出る。**
縁を付ければ、**一つの見た目のままどの床でも浮く。**

**型ごとに色を変えないこと。**変えれば個別には見やすくできるが、
**店を移るたびにプレイヤーが覚え直しになる。**癖は店ではなく人に付くものなので、
見た目は全型で同じにする。

**動かしてよいのは明るさだけで、形は動かさない。**`slow` の三点は、
最初は下から順に灯していた（1点→2点→3点）。**瞬間によっては1点しか出ず、
小さな黄色い点ひとつになって見落とした。**形が変わる動きは「飾り」ではない。
いまは三点とも常に描き、灯っている一つの色だけを変えている。

**雀ドルは頭の上の印と体まわりの物が両方付く**（beat ＋ mark）。
ただの客はどちらか一つだけ。**「二つ付いている子」を遠目に探す**のが、
この画面でやることになる。

**箱の外に出るので、隣の席と重なることがある。**それは許す——
卓の上に牌が乗っているように見えるだけで、誰の印かは位置で分かる。

**四型で確かめる。**並べた比較ではなく、**店の全景から答えを伏せて探す。**
「女性を探す → 印が二つ付いている子を探す」の手順を、四つの型それぞれで踏む
（古い雀荘・場末の店・ガールズ雀荘・高級店。癖6種が一度ずつ出る店を種で選ぶ）。
**見つけられない組み合わせが一つでも残っていれば、まだ足りない。**

**打ち筋20種 → 癖6種の写像**（一つの打ち筋に癖は一つ）:

| 癖 | 打ち筋 |
|---|---|
| `fast` | `speed` 速攻型 / `lasukai` ラス回避 / `balance` バランス |
| `slow` | `judge` リーチ判断職人 / `read` 情報読解 / `perfect` 完成型 |
| `bou` | `menzen` 門前高打点 / `oya` 親番爆発 / `shoubu` 勝負手一点集中 / `top` トップ取り |
| `meld` | `naki` 鳴き特化 / `toitoi` 仕掛け重視 / `some` 染め手 |
| `guard` | `wall` 鉄壁守備 / `betaori` ベタオリ名人 |
| `still` | `chiitoi` 変則手 / `mura` ムラ型天才 / `mental` メンタル連動 / `oorasu` オーラス勝負師 / `gyakkyo` 逆境型 |

**写像は全単射にしない。これは妥協ではなく設計。**
癖が打ち筋を一対一で当ててしまうと、観察は対応表を引く作業になる。
6種に束ねると「攻め型の誰かが3人いる」までしか分からず、
**そこから先はプレイヤーが選ぶ**。それが上達の余地になる。

**観察の報酬**は、声をかけたあと（＝発見したあと）に確定する。
名鑑と同じく `STYLES[c.style].name` が出るので、
**口説くときの対局で相手の打ち筋を知った上で戦える**（§6）。

## 5. 口説くを厚くする

いまは `evaluate` が真偽を返すだけで、満たしていなければ会話すら起きない。

### 5.1 段階

1. **対局の前に相手が一言。**`chara`（19種）で変わる。
   同行者に**同郷**（`region` が同じ）の子がいれば場が和む
   ——これは `RULES.aisho` が既に持っている考えかたと同じもの
2. **対局**（第三段のまま。相手より上の着順で勝ち）
3. **勝ったら交渉。そこで初めて条件が明かされる。**
   `evaluate()` を回し、
   - 満たしていれば契約（第三段のまま）
   - 満たしていなければ **「今は無理だが、○○してくれたら」**と返る。
     `○○` は `evaluate().detail`（既に全 `RULES` に書いてある文面）
4. **空手で帰らせない。**その課題を**依頼として事務所に届ける**
   （第四段の `offers.js` の器をそのまま使う）
5. **負けても `favor` が積まれる**（第三段のまま）

### 5.2 課題は相手ごとに一枠（上書き）

**失敗のたびに積まない。**同じ相手の課題は一件だけで、
新しく会うたびに**上書きで更新**する。朝の画面が溢れないように。

`offers.js` に `kind: 'quest'` を足す。
`once` ではなく **`slot: 'quest:<charaId>'`** を持たせ、
同じ `slot` の依頼は**新しいものが古いものを置き換える**。

```js
{ id: 'quest-22', kind: 'quest', slot: 'quest:22',
  when: () => false,            // ← 自動では発火しない。遠征が直接積む
  once: false, prio: 8, days: 0, members: { min: 0, max: 0 },
  payload: { charaId: 22, detail: '…', region: '関西' } }
```

**`when` は常に偽。**この種だけは `Offers.fire()` が引くのではなく、
**遠征の交渉が `Offers.push(store, quest)` で直接積む。**
`fire` の外に置くのは、発火条件がプレイヤーの状態ではなく
「その相手に会って負けた」という**出来事**だから。
§8.1 の「発火条件を日付にしない」には触れない（日付は見ていない）。

### 5.3 好感度で条件が緩む

`favor` を会いに行くほど積み上げ、**いつか条件が緩む形**にする。
**遠征の日数を払う理由をここに置く。**

`RULES` の判定そのものは変えない。変えるのは**契約金**。

```
契約金 = costOf(chara) × (1 − favor/200)        favor 100 で半額
```

`costOf` は `scout.js` にあり、`evaluate` が呼んでいる。
**`RULES` には触らない**（判定は同じ）。値引きだけが乗る。

`money` と `rank` の条件は緩まない。緩むのは金だけ。
**「通えば安くなるが、格が足りなければ会ってもくれない」**という形。

### 5.4 文面の置き場所（報告）

**`serifu.js` に場面を三つ足す。別に持たない。**

| 場面 | 出る所 | 本数 |
|---|---|---|
| `scoutMeet` | 対局の前の一言 | 19種 × 2 |
| `scoutWin` | 勝ったあと（交渉に入る） | 19種 × 2 |
| `scoutLose` | 負けたあと | 19種 × 2 |

理由：

- `serifu.js` は**すでに `chara` を鍵にした8場面の表**で、
  「人を足すときも `chara` を既存の19種から選べばセリフは自動的に付く」
  （`HANDOVER.md` §4）という決めごとが乗っている。
  **別の表を作ると、キャラを足すときに二か所を埋めることになる**
- 冒頭のコメントが「場面を増やすときは `ui.js` の `say()` を呼ぶ場所も足すこと」
  と書いており、**増やす前提の作り**になっている

**条件の文面（「事務所ランク5が必要です」）は `serifu.js` に書かない。**
それは `RULES` の `detail` が既に持っている。
交渉の一行は **「性格の一言」＋「既存の `detail`」の合成**にする。
条件文を二か所に書くと、片方を直したときに必ずずれる
（`RULES.event` で一度通った話。`office/spec.md` §8.2）。

同郷の一言だけは性格ではなく**関係**の話なので、
`serifu.js` ではなく `scoutshop.js` 側にリテラルで持つ（19本も要らない）。

## 6. 報告：朝に誰がいるかを確定させる置き場所

### 6.1 新しいファイル一つ

| ファイル | 中身 |
|---|---|
| `src/scoutshop.js` | 店の型4種、パレット派生、癖の表、`buildShop()`（純関数） |

const ScoutShop = (() => {

  // STYLE_QUIRK: { [styleKey]: quirkKey }  20 → 6

  function quirkOf(styleKey) -> quirkKey
  function buildShop(st, trip, rng) -> shop                          // **純関数**
  return { SHOP_TYPES, QUIRKS, STYLE_QUIRK, pickType, palOf, quirkOf, buildShop };

### 6.2 いつ引くか

**遠征中の朝に一度だけ**。`office.js` の `runTripDay()` の先頭で、
**留守の店を回すより前に**引く。`jansou/spec.md` §1 と同じ作法で、
**乱数はここで使い切る。**描画層は `shop` を読むだけで引かない。

**滞在日ごとに引き直す。**同じ店の同じ顔ぶれが5日続くと、
一日目に全部見終わって残り4日が空になる。日替わりにすれば
「今日は当たりが濃い」「今日は薄い」が出て、3回の使いどころが変わる。

誰を混ぜるかは **`drawOne` と同じ重み**（`Scout.discoverWeights`）で引く。
プールは**その県の地方の未発見者**（`office/spec.md` §4.4 のまま。
雀ドルが `pref` を持つのは200人増員のとき）。

### 6.3 `trip` に持たせるもの

`trip` は既に最上位のセーブにある。そこへ `shop` を一つ足す。

```js
trip: {
  ...,                       // 第三段のまま（pref, purpose, target, members, deputy, dayLeft, log …）
  shop: {
    day: 12,                 // 引いた日（parlor.day）。**朝に引き直したかの印**
    type: 'old',             // 店の型
    parlor: {                // 描画用の擬似 parlor。**帳簿は持たない**
      tables: 3, interior: 1, auto: 1, sign: 1, rep: 0, day: 0,
      floor: null,           // null なら autoPlace が組む
      shifts: {}, buffs: [], log: [], bottles: [0,0,0,0,0,0],
    },
    name: '雀荘 かどや',      // 店の名前（jansou-guests.js の名前生成を流用）
    seats: [                 // 席に座っている者
      { table: 0, seat: 1, typeKey: 'salary', charaId: null, quirk: null },
      { table: 1, seat: 2, typeKey: 'oldman', charaId: 42, quirk: 'bou', quirk2: 'fast' },
    ],
    staff: [ { charaId: 18, quirk: 'slow' } ],   // 通路に立つ子（引き抜き）
    calls: 3,                // 今日あと何回声をかけられるか
    met: [42],               // 今日すでに声をかけた相手（charaId か席の印）
  },
}
```

- **`shop.day !== parlor.day` なら引き直す。**これが「朝に一度だけ」の印。
  同じ朝を描き直しても顔ぶれが変わらない
  （`office.js` の依頼発火が `firedFor` でやっているのと同じ形）
- **`calls` は日ごとに戻る。**滞在が長いほど機会が増える
- **`shop.parlor` は擬似。**`Jansou.normalize()` は通さない
  （通すと `tables` が最低2に丸められるなど、自分の店の決めごとが混ざる）。
  `JansouFloor` が読むキーだけを持つ

**セーブが膨らむのを警戒すること。**`seats` は最大 6卓×4席＝24件。
一件は5キーなので、`localStorage` の実害は無い。
ただし **`shop` を `parlor` の下に置かないこと**——
`Jansou.normalize()` が知らないキーを捨てる（`HANDOVER.md` §5）。

## 7. 報告：段階の切り方

**三つに割る。**指示のとおりでよい。それぞれ単体で動く状態になる。

### A4.5-1 店を見る

- `src/scoutshop.js`（型・パレット・`buildShop` の席だけ）
- `JansouFloor` に `pal` 引数と `idle()` と `mount(host, {title, bare})`
- 遠征中の朝に、滞在先の店が一枚出る。客とスタッフが立っている。

- **まだ癖は無い。**タップすると誰か分かる（未発見はシルエット）。
  声をかけるのは一日3回まで。これだけで
  **`drawOne` 一回よりは手触りがある**（どこを押すかは選べる）
- **タップできるのは席に座っている子だけ。**当たり判定（`.jnFlHit`）は
  `drawHits()` が `live.seated` にだけ置いているため。
  通路に立つスタッフ（＝引き抜き）は**この段では絵だけ**で、
  押せるようにするのは A4.5-2 以降（`drawHits` に手を入れることになる）

**ここで止めても遊べる。**これが最小の到達点。

**実装で分かったこと（2026年9月3日）**

- **`drawOne` の自動発見は外した。**遠征中に毎日ただで一人見つかると、
  一日3回の上限も、どこを押すかの判断も意味を失う。
  発見は「店を見て、声をかける」だけになった
- **種はそのまま渡してはいけない。**線形合同法（`jansou.js` と同じ式）は
  隣り合う種の一手目がほとんど同じで、`seeded(day)` で引くと
  **毎日同じ型の店が出た。**`ScoutShop.seeded` が種を散らして二手捨てる
- **`measure()` が外れた床で落ちた。**`host.parentNode.clientWidth` を
  読むが、`shell.html` の `go()` は `#view` を空にするだけで後始末の口が無く、
  画面を替えたあとにも `resize` が飛んでくる。
  ガードと、`onResize` が「外れていたら自分で片づける」を足した
  （**自分の店の床にも前からあった穴**）
- **シルエット→顔は床では起きない。**床はドット絵なので、
  見つけた子の写真は下に札で出す（`.ofShopFound`）。名鑑にも載る

### A4.5-2 癖

- `QUIRKS` と `STYLE_QUIRK`、二拍と一拍の割り振り
- `drawActors()` に癖の描画を足す（**`live.clock` だけから**）
- 観察して選べるようになる。**ここで初めて「探す」が成立する**

**実装で分かったこと（2026年9月3日）**

- **癖を二つ持たせるには、系統を分けるしかなかった。**
  6種を素直に引くと雀ドルが `fast` と `slow` を同時に持つことがあり、
  そのときは**片方しか描けない**（どちらも打牌の振りかたなので）。
  結果、二拍のはずの子がただの客と同じ絵になる。
  そこで `QUIRKS` に `kind` を入れ、`beat`（`fast`/`slow`/`still`）と
  `mark`（`bou`/`meld`/`guard`）に割った。
  **雀ドルは片方ずつ、ただの客はどちらか一つ。**
  こうすると「印があって、かつ振りかたが変」＝雀ドル、という
  **二段の観察**になる。§4.3 の狙いはこの形で出た
- **印は 12×16 の中に収めた。**当初は「席の手前」を卓の向きで
  変えることも考えたが、席0/1は卓との隙間が1ドットしかなく `meld` の
  3×2 が入らない。**どの席でも同じ場所に出す**ことにした
  ——この大きさでは「体のどこに付いているか」が唯一の手がかりなので、
  席ごとに動かすほうが読めなくなる
- **印の色は `PAL`（＝ PAL0）から取る。**`pal`（型ごとの上書き）を使うと、
  古い雀荘と高級店で印の色が変わって、型をまたいで癖を覚えられない
- **`bou` と `guard` はどちらも足元に出るので、形で分けた。**
  `bou` は3ドット続きで真ん中が赤、`guard` は1ドットおきに増えていく。
  3倍で並べて撮ったが、混ざらない
- **`slow` の周期は、一度これで外して直した。**
  当初は「3秒止まって、0.6秒のあいだ 6Hz で二拍」にしていたが、
  4秒ぶん毎フレーム拾って測ると**癖なしと同じ4回**で、
  間の長さ（1.2秒 対 2.3秒）でしか区別できなかった。
  **振る回数そのものを半分にして**、一周期に一度だけ上げて下ろす形にした。

  | | 手を上げている割合 | 止まっている最長 | 4秒間の振り |
  |---|---|---|---|
  | 癖なし（既定） | 31% | 1.2秒 | 4回 |
  | `slow` | 7% | 2.3秒 | **2回** |
  | `fast` | 34% | 0.28秒 | 18回 |
  | `still` | 0%（肩だけ上下） | — | 0回 |

  **この測りかたを、癖の周期を動かすときの物差しにすること。**
  絵を見比べても「なんとなく遅い」までしか言えない
  （`tools/` には置いていない。`JansouFloor` の `use` の `href` を
  毎フレーム拾って数えるだけなので、そのつど書けばよい）
- **自分の店に出ないことは、`jansou.js` に `quirk` の字が無いことで担保した。**
  `test-scout.js` が機械的に見ている。ブラウザでも、役者の `<g>` の中に
  印の色の矩形が一つも無いことを確かめた（遠征先の店では出る）

### A4.5-3 交渉

- `serifu.js` に3場面 × 19種 × 2本
- `evaluate()` の前後を組み替え（判定そのものは触らない）
- `offers.js` に `kind: 'quest'` と `slot`（相手ごとに一枠・上書き）
- `costOf` に `favor` の値引き

**実装で分かったこと（2026年9月3日）**

- **課題は静的な表に載せた。**`st.offers` は `{id, kind}` しか持たず、
  中身は `Offers.byId` が表から引く形なので、動的に作った依頼は
  **セーブから戻せない。**そこで雀ドル一人につき一件を最初から
  `TABLE` に置き（`when` は常に偽なので `fire` は引かない）、
  `push()` が `slot` で置き換える。表は 15件 → 15＋雀ドルの数になった
- **課題に文面を焼き込まなかった。**`payload.detail` に文字列を持たせると、
  条件が変わったときに札だけ古びる。`textOf` がそのつど
  `Scout.evaluate` を引くようにしたので、**条件は一か所（`RULES`）のまま**
- **`office.js` が条件文を書き写していないことを、機械的に固定した。**
  `tools/test-scout.js` が `office.js` の本文を読んで
  「事務所ランク」「〜が必要です」などが無いことを見る。
  **コメントは外してから見ること**——「ここに条件文を書くな」という
  注意書き自体が条件文を例に挙げているので、素の本文で見ると必ず引っかかる
- **好感度の増減を純関数に出した**（`Office.favorGain` / `addFavor`）。

- **吹き出しの幅は 360px。**`.popupBox` の既定（400px）のままだと
  380px の端末で左右の余白が消える。`.ofSayBox` で絞った
- **`office.html` に `serifu.js` を足した。**単体ページで
  `SERIFU` が無いと一言が出ない（落ちはしないが、場面が空になる）

**再測を見て決めたこと（2026年9月3日）**

`tools/measure-office.js` の §5 を回して、§8 に残っていた二つ
（**ただの客に癖が付く割合25%**・**`CALLS_PER_DAY` の3**）を
**どちらも動かさない**と決めた。根拠は三つ。

- **無作為に押すと県の規模がほとんど効かない**（滞在2日で 0.49 / 0.67 / 0.53）。
  席が増えるぶん薄まって、雀ドルの居やすさと相殺されている。
  **これは設計どおり。**規模が実りに変わるのは癖を読んだときだけで、
  **観察が「地理の有利さ」を引き出す鍵**になっている。
  25% を下げると癖がもっと当たるようになるが、
  同時に**読まなくても当たる**方向に寄る（癖の付いた席が減って的が絞れる）。

### 10.2 声をかけた結果の内訳

男性に声をかけると、三つのうち一つが起きる。

| 結果 | 何が起きるか |
|---|---|
| **何も起きない** | 「……」で終わる。回数だけ減る |
| **話す** | 「今日はあの子はいないよ」／「さっき長考してた子がいたな」——**その日の店についてのヒント** |
| **誘われる** | 「打っていくか」。受ければ対局（§10.3） |

#### 割合と、その根拠

```
誘われる = 0.15 + 0.35 × (癖が付いているか) + 0.20 × (認められた度合い/100)   上限 0.75
話す     = 残りの 0.30
何も起きない = 残り
```

**癖が付いている男は誘ってくる。**これがいちばん大事な項。
`PLAIN_QUIRK = 0.25` で「ただの客の四人に一人に癖が付く」ことは既に決まっていて、
その理由は §4.3 に**「打てる常連はいる」**と書いてある。
**その伏線をここで回収する**——一拍の癖が付いた男は「打てる客」で、
**声をかける前に床の上で見えている。**

つまり観察の技がそのまま移る。

- **二拍（頭の印＋体の物）が付いた女** … 雀ドル。声をかければ発見
- **一拍が付いた男** … 打てる客。誘ってくる見込みが 0.50
- **無印** … 誘ってくる見込みは 0.15

**全員が誘うわけではない**が、**誰が誘いそうかは見て分かる。**
これで「どの男に声をかけるか」も判断になる（無作為に押す人と、
癖を読む人とで差が付く——A4.5 の再測で女について出たのと同じ構造）。

**「話す」はヒントを返す。**返す内容は二つだけ。

- **その日、雀ドルが店にいるか**（`shop.seats.some(charaId)`）
  →「今日は見ない顔はいないな」／「一人、初めて見る子がいたよ」
- **いるなら、その子の癖の系統を一つ**（頭の印か、体の物か、どちらか片方）
  →「さっき長考してた子がいたな」

**片方しか言わない。**両方言うと二拍がその場で特定でき、観察が要らなくなる。
**空振りが「情報」に変わるが、答えにはならない**——ここが設計の勘どころ。

#### 通うと、話の中身が変わる（`local` の二つめの見せかた）

**土地に馴染んだことを、数字ではなく言葉で出す。**
`local` は §10.4 で「雀ドルの出やすさ」と「誘われやすさ」という**数字**に効くが、
それだけだと**上がっていることがプレイヤーに見えない。**
だから「話す」の**踏み込みかた**を三段にする。

| `local` | 呼ばれかた | 返ってくる話 |
|---|---|---|
| **0〜24**　よそ者 | 「兄ちゃん」 | **その日の有無だけ。**「今日は見ない顔はいないよ」 |
| **25〜59**　顔は知られた | 「兄ちゃん」 | **有無＋癖の系統を片方。**「さっき長考してた子がいたな」 |
| **60〜100**　常連 | 「社長さん」 | **踏み込む。**「あの子なら夕方に来るよ」「今日はもう帰った」——時間帯や、席のあたり |

**返す情報の量は §10.2 のまま増やさない**（癖の系統は片方だけ）。
**変わるのは言いかたと、そこに付く一言。**
「あの子なら夕方に来る」は**その日の中では使えない**（滞在はその日で終わる）ので、
**情報としては効かず、関係としてだけ効く**——それでいい。
**数字が上がったことを、プレイヤーは会話の距離で知る。**

呼ばれかたが変わるのがいちばん効くはず。**「兄ちゃん」から「社長さん」**になるのは、
一度でも言われれば覚える。`local` の帯は三つだけにして、
**上がった瞬間が一度きりの出来事**になるようにする（毎回少しずつ変えない）。

文面の置き場所は `scoutshop.js`（§5.4 の `aishoLine` と同じ考え——
性格ではなく関係の話なので `serifu.js` に置かない）。
**実装は A7-3**（`local` が入ってから。§10.6）。

### 10.3 対局の形

| | 決めごと | 理由 |
|---|---|---|
| **長さ** | **一局**（`Game` の `length: 'ikkyoku'`。既にある） | 口説く遠征の対局は東風一回で、そちらが**重い一戦**。**軽い一局**と使い分ける。日の中に収める |
| **卓** | 打つ人 ＋ 誘った客 ＋ 同じ店の客2人 | 店の中の話なので、席から拾う |
| **勝ち** | **誘った客より上の着順**（`口説く` と同じ判定の形） | 判定の言いかたを増やさない |
| **打つ人** | **代表か、同行者の誰か。**受けるときに選ぶ | 同行枠が「連れて行くと店が薄くなる」だけでなく、**対局の戦力**になる（`ROADMAP.md` §6） |
| **疲労** | **打った人に +4。**代表は疲れない（代表は `fatigue` を持たない） | 疲労は所属の子のものという既存の形を崩さない |
| **日数** | **食わない。**その日の中で収まる | `dayLeft` の意味を増やさない。遠征の日数は「その土地をまわる日数」（§4.3） |
| **声かけ** | **1回使う**（外しても使うのと同じ） | §10.5 のトレードオフの本体 |

**打つ人の選ばせかた。**誘われた札に、代表と同行者が顔で並ぶ。押した人が打つ。

- **代表** … 疲れないが、強さは段位どまり（`Taikai.PLAYER_STRENGTH` D46〜S78）
- **同行者** … `comp` が高ければ強いが、**+4 の疲労を払う**。疲労と調子は
  既存の `Office.tableCardOf` を通るので、疲れている子は弱くなる（新しい経路を作らない）

**強い子に打たせるほど勝てるが、その子が疲れる。**遠征は1日 +11 が既に乗っているので、
**同行者に毎日打たせると帰る頃には限界に近い。**ここが選ばせる意味。

**実対局か数値処理かは既存の分岐に乗せる**（`playOrSimulate`）。
`index.html` では実対局、単体ページでは `simulateTable`。
**`store.playRealMatch` に `length` を渡せるようにする**のが唯一の配線の追加。

### 10.4 認められた度合い（`local`）

#### 置き場所

```
st.local = { [prefKey]: 0..100 }      // 最上位。parlor の下ではない
```

**`parlor` の下に置かない**（`Jansou.normalize()` が知らないキーを捨てる）。
既定値は `shell.html` の **`blankState()` / `loadState()` / `onStart`** の**三箇所**に書く
（`condDay` と `mailRead` で二度踏んだ罠）。

#### 何がどれだけ上がるか

| できごと | 上がり |
|---|---|
| 誘いに勝つ | **+8** |
| 誘いに負ける | **+3** |
| 「話す」が出た | **+1** |
| 上限 | **100。減らない**（`ROADMAP.md` §1「回復しきる方向」と同じ姿勢） |

**負けても上がる**のは、口説くの好感度（勝ち12／負け5）と同じ考えかた。
**空手で帰らせない**（§5.2）。

#### 何に効くか（二つだけ）

1. **雀ドルが出やすくなる**（本命）
   ```
   ANY_CHANCE[i] + 0.20 × local/100      上限 0.85
   TWO_CHANCE[i] + 0.15 × local/100
   ```
   規模1の県で 0.35 → 0.55。**「まだ誰にも見つかっていない県」が、
   通えば見つかる県になる**（`ROADMAP.md` §2 の「規模の小さい県は
   『弱い』ではなく『まだ誰にも見つかっていない』」がここで効く）
2. **誘われやすくなる**（§10.2 の式の第三項）。顔が知られるほど声が掛かる

**三つめは足さない。**契約金が下がる、条件が緩む、は好感度（`favor`）の役目で、
そちらと二重になる。**`local` は土地、`favor` は人。**

#### 通う理由になっているか

4日の遠征で毎日1回打ち、半分勝てば **+22**。max まで**3回ぶんの遠征**。
一度の遠征では割に合わず、**同じ県に通うと効いてくる**——狙いどおりの形。
ただし**遅すぎると誰も通わない**ので、`+8/+3` と `0.20` は
**A7-3 の再測で動かす前提の初期値**（§10.6）。

### 10.5 声かけ3回とのトレードオフ（見積もり）

|---|---|---|
| 1回 | 0.21人 | **−8%** |
| 毎日1回（4回） | 0.85人 | **−33%** |

#### 何回通えば max か（実機で三回通った）

鳥取（規模1）へ4日の遠征を三回。押しかたは「二拍の女 → 一拍の男」の順。

| | 見つけた | 打った | 話した | `local` |
|---|---|---|---|---|
| 一回目 | 3人 | 1回 | 2回 | **10** |
| 二回目 | 1人 | 4回 | 1回 | **43** |
| 三回目 | 2人 | 2回 | 0回 | **59** |

**一回目に打てないのは、雀ドルがいて声かけをそちらに使うから**（A7-2 で分かったこと）。
二回目以降は空振りの日に打てるので、**一回の遠征でおよそ +25。**

- **「顔は知られた」（25）は二回目で届く**
- **「常連」（60）は三回目〜四回目**
- **max（100）は五回**

**遅すぎない、というのが答え。**設計の懸念（「伸びが遅ければ埋まっただけで終わる」）は
実機では出なかった。**`+8/+3` と `0.20` は動かさない。**

※ 上の三回は代表（段位B）が打って七戦全勝している。序盤の D級で半分負けると
一回 +22 ほどになるが、**max まで五回**は変わらない（100/22 ≒ 4.5）。

**やらないこと**
- 男性を図鑑に載せる。**名前も付けない**（客タイプの通称のまま）
- `local` を減らす仕組み。取り返しのつかない損失を置かない
- 対局に賭け金を付ける。金は中盤以降どうにでもなるので、判断にならない
