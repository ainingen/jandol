## 他の作業を待っているもの

### ローカルルール（卓ごとのルール差）

雀荘や大会によってルールが違う、という仕組み。喰いタンあり／なし、割れ目、赤の枚数、
一発裏など。臨場感のために入れたい。

**着手前提：**対局画面の改装が `main` に入っていること。

**先にやる小さいこと**（これだけ切り出して先行してよい。**2026年9月5日に入れた**）

`Game` のコンストラクタに `opts.rules` を受け取る口を開け、既定値 `RULES_DEFAULT` を
一つ置く。**`undefined` なら既定に落ちること。**分岐は一つも実装しなくてよい。

理由が二つ。`opts` を受け取る形にしたばかりなので、口を開けるのはいまが一番安い。
**後回しにすると、実装時に「ルールをどこから読むか」を全ファイルで探すことになる。**
そして雀荘や大会にルールを持たせると `state` にルール設定が乗るので、
**前方互換の形を最初に作っておかないと既存のセーブを壊す。**

**設計方針**（実装時に詰める）

**個別のトグルにしないこと。**喰いタン・後付け・割れ目・赤の枚数・一発裏・ハコ下・
順位点を全部トグルにすると数百通りになり、**AI の押し引きが全組み合わせで
正しいかを検証できない。**`test-jansou` が71,534件通っているのは、いまルールが一つだから。

**3〜4種類の「卓」として束ねる。**

- 標準ルール — 喰いタンあり・赤あり。大半の大会
- 競技ルール — 喰いタンなし・赤なし・一発裏なし。格の高い大会
- 祝儀ルール — 赤多め・割れ目あり。雀荘の日常

プレイヤーは組み合わせを選ばず「今日はどの卓か」を知るだけ。
**検証すべき組み合わせが3〜4に収まり、臨場感はむしろ強くなる。**

**ルールの表示**

麻雀のルール差は**打ち方が変わる**ので、対局が始まってから調べるものではない。
**卓に着く前に出すこと。**`taikai.js` の「対局の設定」の隣に「この卓のルール」を常設し、
**標準と違う点だけ**を目立つ色で出す。「喰いタンなし」の一行があれば打ち方が変わる。
押して詳しい説明が出るのは、そのうえでの補助。

**動かす前に：**`RULES_DEFAULT` は**いまの `engine.js` の実際の振る舞いを写したもの**で、
理想の既定値ではない（喰いタンあり・赤3枚・一発裏あり・割れ目なし・ハコ下で終了）。
分岐を入れるときは、**まず既定のまま通ることを確かめてから**片方ずつ倒すこと。

### pop / favor / local の調査と画面表示

指示書は `INSTRUCTIONS_pop_favor_survey.md` に書いてあります。**A7-3（`local` で「話す」の踏み込みが三段になる）より前に調査を通す**という前提で書いてあるので、A7-3が先に入った場合は前提を読み直してください。

知りたいことの中心は2つ。

- `favor` は `Scout.costOf()` が契約金の値引きに使っているが、**実際に加算される経路が動いているか**。貯まらないなら値引きは死んだ機能で、貯まっているならプレイヤーに何も見えないまま契約金が下がっている
- `favor`（契約金の値引き）と `local`（会話の踏み込み）は**どちらもプレイヤーと相手の距離を表す数字**で、住み分けがついているか。同じ行動で両方上がるなら、プレイヤーには「なぜか数字が2つ動く」としか見えない

**動かす前に：**麻雀UIが `office.js` / `jansou.js` に触っているなら、そこと重なります。
